Tú hablas con el asistente, y el asistente llama a las herramientas. Esta página recorre siete peticiones habituales de principio a fin: qué pedir, qué llamadas hace el asistente y en qué orden, y en qué fijarse en la respuesta. Las llamadas se muestran con los argumentos que envía el asistente, para que las reconozcas en un cliente que enseña las llamadas a herramientas, y cada nombre de argumento es el que documenta [Herramientas](/libgen-mcp/es/tools/).

Dos cosas valen para todas:

- **Los resultados citan a terceros.** Los títulos, las descripciones y el texto extraído son datos que el asistente lee, nunca instrucciones que obedece.
- **Un servidor remoto devuelve enlaces.** En el [endpoint alojado](/libgen-mcp/es/hosted/) o en cualquier despliegue con `--http`, `download` responde con un enlace directo en lugar de guardar un fichero. `read` solo está donde el operador lo ha activado, como en el endpoint alojado, y aun así nunca acepta una `path` local.

## Encontrar una edición concreta de un libro

> Encuentra la tercera edición del volumen 1 de _The Art of Computer Programming_ de Knuth, en PDF.

El asistente busca en el catálogo y ordena para que las ediciones sean fáciles de comparar:

```json
{
	"query": "Art of Computer Programming Knuth",
	"topics": ["nonfiction"],
	"order": "year",
	"order_mode": "desc"
}
```

Cada fila lleva `year`, `edition`, `extension`, `size`, `pages` y el `filename` original, que es lo que distingue dos ediciones cuando el catálogo deja vacío el año. Si conoces el ISBN, una búsqueda solo en ese campo es más precisa:

```json
{ "query": "9780201896831", "search_in": ["isbn"] }
```

Antes de descargar, `get_details` con el `md5` de la fila elegida confirma la edición, la editorial y los ISBN, y después `download` recibe ese mismo `md5`:

```json
{ "md5": "<md5 de la fila elegida>" }
```

Un `verified: true` en la respuesta significa que los bytes guardados dan ese md5. El prompt `acquire_book` pide todo este recorrido de una vez, con `title` y, si quieres, `author`, `format` y `language`.

## Conseguir una copia en acceso abierto de un artículo

> Descarga el artículo con DOI 10.1038/nature12373.

Basta una llamada:

```json
{ "doi": "10.1038/nature12373" }
```

`download` ofrece el DOI primero a las fuentes de acceso abierto (OpenAlex, Europe PMC, bioRxiv, Zenodo y las demás), después a los recursos de reserva, y guarda la primera copia que sirva una de ellas. Cada paso, qué preparar y qué hacer si falla, está en [Descargar un artículo por DOI](/libgen-mcp/es/download-a-paper/). Para probar una sola fuente y ninguna más, nómbrala, por ejemplo `"source": "openalex"`. El prompt `get_paper` acepta el mismo DOI, o en su lugar una cita en texto libre.

## Revisar la literatura sobre un tema

> Encuentra artículos recientes en acceso abierto y un par de libros sobre retrieval-augmented generation, y hazme una lista de lectura.

Para los artículos, el asistente busca más allá del catálogo a propósito, porque los preprints y la obra en acceso abierto a menudo solo están ahí:

```json
{
	"query": "retrieval-augmented generation",
	"topics": ["articles"],
	"extra_sources": "always",
	"year_from": 2023
}
```

`year_from` es lo que lo hace reciente. A los proveedores cuya API puede filtrar por año se les pide que lo hagan, y cualquier otro resultado, incluidos los del catálogo, se comprueba al llegar, de modo que el intervalo se cumple en toda la respuesta. Un registro del catálogo sin año se deja fuera y se cuenta en `year_filtered`.

Las coincidencias del catálogo, y las de Anna's Archive, vuelven como filas, y las de los demás proveedores en una lista `open_access` aparte, cada una marcada con su `origin`. El origen dice qué hacer después: un resultado de `crossref`, `europepmc`, `dblp` o `pubmed` suele llevar un DOI para `download`, uno de `arxiv`, y uno de `openalex` cuya copia gratuita conoce OpenAlex, lleva un `pdf_url` que el asistente descarga directamente, y solo uno marcado `open_access: true` afirma que se puede leer gratis. Una segunda búsqueda sin `topics` encuentra los libros. [Cómo funciona la búsqueda](/libgen-mcp/es/how-search-works/) explica las etiquetas.

El prompt `research_topic` hace esta revisión por ti, con `topic`, `kind` (`articles`, `books` o ambos) y `limit`, y pide al final una bibliografía anotada.

## Montar una bibliografía

> Dame BibTeX de estos tres libros y RIS de los dos artículos, para Zotero.

Para cada elemento, el asistente llama a `get_details` con el identificador que ya tiene:

```json
{ "md5": "<md5 de un resultado de búsqueda>" }
```

```json
{ "doi": "10.1016/j.cell.2011.02.013" }
```

El registro lleva un campo `citations` con una entrada `bibtex` y un registro `ris`, más `doi_status`, que dice si Crossref confirmó el DOI. Un DOI que no se pudo confirmar se deja fuera de las entradas en lugar de pegarlo en una referencia a la que quizá no pertenece. La respuesta en Markdown solo muestra el BibTeX, así que pide el RIS de forma explícita cuando lo quieras. Qué identificador da la entrada más completa, y por qué falta a veces un DOI, está en [Citas](/libgen-mcp/es/citations/).

Una bibliografía en un estilo concreto es un argumento más:

```json
{ "doi": "10.1016/j.cell.2011.02.013", "cite_as": ["apa", "vancouver"] }
```

`cite_as` acepta cualquiera de `apa`, `mla`, `chicago`, `harvard`, `vancouver`, `ieee` y `csl-json`, y cada estilo vuelve bajo su propio encabezado, que dice cómo se hizo. Un registro cuyo DOI confirmó Crossref lo formatea la agencia que registró el DOI, a través de doi.org. Cualquier otro registro, un libro encontrado por md5 por ejemplo, recibe el estilo construido a partir de sus propios campos, y una parte se omite en lugar de adivinarse cuando el campo está vacío.

Una referencia que llega como texto, copiada de la lista de referencias de un artículo, no necesita búsqueda previa:

```json
{ "citation": "LeCun Y, Bengio Y, Hinton G. Deep learning. Nature 2015" }
```

Crossref la resuelve al DOI de la única obra que coincide con claridad, y la respuesta nombra ese DOI para que compruebes que es la obra que querías. Cuando ningún candidato gana con claridad, la respuesta lista los candidatos y no devuelve registro, en lugar de citar una obra que el texto nunca nombró.

## Seguir las referencias y las citas de un artículo

> ¿En qué artículos se apoya _Deep learning_ de LeCun, Bengio y Hinton, y qué artículos posteriores lo citan más?

El asistente pide a `get_details` las obras relacionadas, una vez en cada dirección:

```json
{ "doi": "10.1038/nature14539", "related": "references", "related_limit": 10 }
```

```json
{ "doi": "10.1038/nature14539", "related": "cited_by", "related_limit": 10 }
```

Las dos respuestas vienen de OpenAlex: el total que cuenta y después una tabla de obras con título, año, DOI, una marca de acceso abierto y cuántas veces se cita cada una, las más citadas primero. Cada DOI de la tabla va directo a `download`, o de vuelta a `get_details` para seguir el recorrido. `related_limit` va de 1 a 25 y vale 10 por defecto. Un registro sin DOI, o con uno que Crossref no confirmó, dice que la lista no está disponible, porque a OpenAlex se le pregunta por DOI. Sin clave, las consultas comparten la cuota diaria que OpenAlex concede a una dirección, y `LIBGEN_MCP_OPENALEX_KEY` la amplía.

## Leer y resumir un capítulo

> Resume el capítulo sobre análisis amortizado de este libro y cita dónde define el método del potencial.

`read` funciona sin guardar el libro entero en ningún sitio que tengas que mirar. El asistente pide primero la tabla de contenidos, solo el nivel superior:

```json
{ "md5": "<md5>", "outline": true, "max_depth": 1 }
```

El índice numera cada entrada y da su página, y el asistente lee el capítulo por su número, o por su título:

```json
{ "md5": "<md5>", "section": "17" }
```

Una lectura por sección empieza donde empieza la entrada y se detiene donde comienza la siguiente entrada del mismo nivel o de uno superior, y el campo `section` de la respuesta dice hasta dónde llega el capítulo. Cuando `has_more` es true, devuelve el `cursor` recibido para el siguiente fragmento del mismo capítulo, y `has_more` pasa a false al final del capítulo, no del libro. Un título que coincide con más de una entrada, como un "Exercises" que se repite, se rechaza con las entradas coincidentes listadas, para que el asistente elija una por número. Para encontrar un pasaje en lugar de leer de corrido, busca dentro del documento:

```json
{ "md5": "<md5>", "find": "potential method", "max_matches": 5 }
```

Cada coincidencia trae su página y un fragmento. Un libro que ya descargaste se lee por `path` en lugar de por `md5`, siempre que esté dentro del directorio de trabajo, el temporal o el de descargas. Un libro escaneado sin capa de texto vuelve con `extractable: false`: no hay OCR.

<Aside type="note">
	Leer por `path` necesita un servidor local. El [endpoint
	alojado](/libgen-mcp/es/hosted/) lee solo por `md5` o `doi`. En un despliegue
	remoto que no sirve `read`, el asistente descarga con su propia herramienta el
	enlace que devuelve `download` y lee el fichero en local.
</Aside>

## Comprobar a qué apunta una referencia

> Esta lista de referencias cita 10.1371/journal.pmed.0020124 para _Antifragile_. ¿Es correcto?

El asistente consulta el DOI en lugar de fiarse de él:

```json
{ "doi": "10.1371/journal.pmed.0020124" }
```

La respuesta muestra el título del registro al que llega el DOI, y `get_details` pregunta a Crossref a qué título tiene registrado ese DOI. Aquí no coinciden: Crossref lo tiene registrado para el artículo de Ioannidis _Why Most Published Research Findings Are False_, así que un registro que lo empareja con el libro vuelve con `doi_status: "mismatch"`, y su línea `provenance` nombra la obra real. Cuando el catálogo no tiene el DOI en absoluto, los metadatos de Crossref ocupan su lugar, marcados `origin: "crossref"`, y un DOI que tampoco conoce Crossref, un conjunto de datos de DataCite o un artículo de mEDRA, recibe el registro que sirve su propio registro a través de doi.org, marcado `origin: "doi.org"`. Para una referencia sin DOI, `get_details` con la referencia como `citation` encuentra el DOI que nombra, o lista los candidatos que comparar cuando ninguno coincide con claridad.
