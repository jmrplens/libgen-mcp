Un host de plugins puede instalar un servidor MCP desde un repositorio cuando el repositorio se describe en un manifiesto que el host entiende. Este repositorio lleva tres archivos para eso, en los dos formatos que leen hoy los hosts. No contienen el servidor: le dicen a un host cómo arrancarlo, y lo que arrancan es el [lanzador de npm](/libgen-mcp/es/install/npm/), ejecutado con `npx`.

## Qué obtienes

| Archivo               | Formato                                                                     | Qué dice                                                                                                                    |
| --------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `plugin.json`         | [Agent Plugins](https://agent-plugins.org/) 1.0, en la raíz del repositorio | El nombre, la versión, la descripción, el autor, la licencia y las palabras clave del plugin. Su esquema no admite nada más |
| `.plugin/plugin.json` | Open Plugins, validado por `.plugin/plugin.schema.json` a su lado           | La misma identidad, más un `logo` y `"mcpServers": "./mcp.json"`, el puntero a la entrada del servidor                      |
| `mcp.json`            | Configuración MCP de Agent Plugins 1.0, a la que llevan los dos             | Una entrada stdio, `libgen`, que ejecuta `npx -y @jmrp.io/libgen-mcp`                                                       |

Los dos manifiestos son archivos separados y no una copia, porque los formatos no coinciden: Agent Plugins 1.0 fija `additionalProperties: false` y no tiene campo para un logo ni para la entrada del servidor, mientras que Open Plugins espera los dos. Un host Agent Plugins encuentra `mcp.json` por su sitio fijo en la raíz del plugin; un host Open Plugins sigue el puntero. Los dos manifiestos llevan la versión de la release, que estampa el workflow de release.

## Qué hosts los leen

Un host que implementa **Agent Plugins** lee `plugin.json` en la raíz del directorio del plugin y `mcp.json` a su lado. Un host que implementa **Open Plugins** lee `.plugin/plugin.json` y sigue su puntero `mcpServers`. Ninguna de las dos especificaciones define cómo se distribuye o se instala un plugin, así que la orden es cosa de tu host y de su versión: normalmente le das el repositorio, `jmrplens/libgen-mcp`, a través de su instalador de plugins, y él copia el directorio a su propio almacén de plugins.

## Requisitos

| Requisito | Detalle                                                                                                                     |
| --------- | --------------------------------------------------------------------------------------------------------------------------- |
| Un host   | Uno que instale paquetes Agent Plugins u Open Plugins con servidores MCP                                                    |
| Node.js   | 18 o posterior, con `npx` en el `PATH` con el que el host arranca servidores. Node ejecuta solo el lanzador, no el servidor |

## Qué ejecuta el plugin

El `mcp.json` completo:

```json
{
	"$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
	"mcpServers": {
		"libgen": {
			"type": "stdio",
			"command": "npx",
			"args": ["-y", "@jmrp.io/libgen-mcp"]
		}
	}
}
```

Está escrito según las reglas de Agent Plugins 1.0, que son las más estrictas que aplica un host, así que un host que acepta archivos menos estrictos también lo acepta:

- **`$schema` y `type` están porque la especificación los exige.** Un host conforme desactiva un `mcp.json` sin `$schema` y se salta una entrada de servidor sin `type`.
- **No hay bloque `env`.** Un host conforme expande exactamente dos marcadores, `${PLUGIN_ROOT}` y `${PLUGIN_DATA}`, y pasa cualquier otro `${...}` al servidor como texto, así que una entrada no puede dar un valor por defecto a una variable como lo haría una shell. Todos los ajustes son opcionales, así que la entrada no fija ninguno, y el servidor lee su configuración de [`~/.libgen-mcp.env`](/libgen-mcp/es/configuration/) y del entorno que le pase el host.
- **Ejecuta un proceso en tu máquina, no un contenedor.** `npx` descarga el lanzador y el binario de tu plataforma en el primer arranque y arranca el binario. Los archivos que guarda `download` quedan por tanto en tu disco, en `~/Downloads` salvo que fijes `LIBGEN_MCP_DOWNLOAD_DIR`, y `read` puede abrirlos, igual que cualquier otro archivo de los directorios que admite.
- **`-y`** responde a la pregunta de npx «¿instalar este paquete?», que un host no tiene forma de contestar.

## Verificar lo que instalaste

Los manifiestos son configuración, así que no hay nada firmado en ellos. Lo que se ejecuta es el paquete de npm, y la [página de npm](/libgen-mcp/es/install/npm/#verificar-lo-que-instalaste) tiene las comprobaciones de procedencia y de firma.

## Dónde queda en el disco

El host copia el directorio del plugin a su propio almacén, en el sitio que elija (la especificación Agent Plugins usa `~/.agents/plugins/<name>/` como ejemplo). npx guarda el lanzador y el binario en su caché, como muestra la [página de npm](/libgen-mcp/es/install/npm/#dónde-queda-en-el-disco). Lo que escribe el servidor una vez en marcha está en la [instalación](/libgen-mcp/es/install/overview/#lo-que-comparten-todos-los-canales).

## Configurar un cliente

En este canal, el `mcp.json` del plugin es la configuración: el host lo lee y arranca la entrada. Los ajustes van en `~/.libgen-mcp.env`, un `NOMBRE=valor` por línea, que el servidor lee al arrancar:

```bash
LIBGEN_MCP_DOWNLOAD_DIR=/home/you/Books
LIBGEN_MCP_UNPAYWALL_EMAIL=you@example.com
```

Cada variable se describe en [Configuración](/libgen-mcp/es/configuration/). En un host sin soporte de plugins, pon la misma entrada en la configuración del propio cliente, y añade allí un objeto `env` si lo prefieres: el archivo de un cliente sigue las reglas del cliente, no las de la especificación. Dónde lo guarda cada cliente está en [Conectar un cliente](/libgen-mcp/es/clients/).

## Actualizar

La versión del manifiesto se mueve con cada release, pero `npx` puede seguir arrancando la copia que ya tiene en su caché. Vaciar esa caché hace que el siguiente arranque descargue la release más reciente:

```bash
npm cache clean --force
```

Un host que ya tiene el servidor en marcha conserva el proceso antiguo hasta que lo reinicia. Para elegir tú la release, fíjala como se explica abajo.

## Fijar una versión

En tu copia local de la entrada, nombra la versión: `"args": ["-y", "@jmrp.io/libgen-mcp@%%VERSION%%"]`. La [página de npm](/libgen-mcp/es/install/npm/#fijar-una-versión) tiene los detalles.

## Desinstalar

Quita el plugin como documente tu host. No se instaló nada de forma global; `npm cache clean --force` borra la copia de npx si quieres eliminarla. Los ajustes, las cachés y las descargas no se tocan; la instalación dice [dónde están](/libgen-mcp/es/install/overview/#lo-que-comparten-todos-los-canales).

## Notas por plataforma

La misma entrada funciona en Linux, macOS y Windows, en x64 y arm64, y eso importa porque ninguna de las dos especificaciones tiene variantes por plataforma de una entrada. En Windows `npx` es un script `.cmd`, y la especificación Agent Plugins permite que un host lo arranque a través del intérprete de órdenes; un host que no lo haga no conseguirá arrancarlo, y la solución es la forma `cmd /c` de [Conectar un cliente](/libgen-mcp/es/clients/).

## Problemas habituales

**No aparece ningún servidor MCP, o el host dice que no encuentra `npx`.** El host arranca los servidores con un `PATH` que no llega a Node. Instala Node 18 o posterior donde llegue ese `PATH`, o da en la configuración del propio host la ruta absoluta de `npx`.

**El primer arranque es lento.** npx descarga el lanzador y el binario una vez; los arranques siguientes usan la caché.

**Un ajuste de `~/.libgen-mcp.env` no tiene efecto.** El host pasó la misma variable con un valor propio, que gana sobre el archivo. La precedencia está en [Configuración](/libgen-mcp/es/configuration/).

Los demás canales se comparan en la [instalación](/libgen-mcp/es/install/overview/).
