`libgen-mcp` expone cuatro herramientas MCP: [`search`](#search), [`get_details`](#get_details), [`download`](#download) y [`read`](#read). Las cuatro están anotadas con una pista de mundo abierto; `search`, `get_details` y `read` son de solo lectura, y `download` es no destructiva e idempotente. Cada handler es a prueba de panics: un fallo inesperado se devuelve como error de herramienta, nunca como una caída de la sesión.

Cada resultado se devuelve por dos canales: la salida JSON estructurada que se documenta más abajo, y una representación Markdown legible en el contenido de texto. Para `search`, el Markdown es una tabla de resultados que incluye los enlaces de descarga de cada resultado. La salida estructurada empieza por un campo `next_steps`; la representación Markdown cierra con esa misma guía bajo un encabezado _Next steps_. La guía de búsqueda le indica al modelo que incluya los enlaces de descarga al presentarte los resultados.

## search

`search` es la herramienta que consulta el catálogo de Library Genesis y, cuando la política `extra_sources` lo permite, los ocho proveedores que hay más allá. Devuelve una página de resultados de archivos con metadatos, hashes MD5 y opciones de descarga por resultado, más metadatos de paginación.

### entrada de search

| Parámetro          | Tipo     | Requerido | Descripción                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | -------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `query`            | string   | sí        | Texto de búsqueda.                                                                                                                                                                                                                                                                                                                                           |
| `topics`           | string[] | no        | Colecciones donde buscar: `nonfiction`, `fiction`, `articles`, `magazines`, `comics`, `standards`, `fiction_rus`. Omítelo para todas.                                                                                                                                                                                                                        |
| `search_in`        | string[] | no        | Campos a coincidir: `title`, `author`, `series`, `year`, `publisher`, `isbn`. Omítelo para coincidir con todos los campos.                                                                                                                                                                                                                                   |
| `results_per_page` | int      | no        | Resultados por página: `25`, `50` o `100`. Por defecto `25`.                                                                                                                                                                                                                                                                                                 |
| `page`             | int      | no        | Página de resultados, empezando en `1`. Por defecto `1`.                                                                                                                                                                                                                                                                                                     |
| `order`            | string   | no        | Ordenar por: `id`, `time_added`, `title`, `author`, `year`, `size`.                                                                                                                                                                                                                                                                                          |
| `order_mode`       | string   | no        | Dirección de orden: `asc` o `desc`.                                                                                                                                                                                                                                                                                                                          |
| `extra_sources`    | string   | no        | Cuándo buscar más allá del catálogo de Library Genesis (Anna's Archive, arXiv, Crossref, OpenLibrary, Project Gutenberg, dblp, PubMed, ERIC): `auto` los consulta solo cuando el catálogo no encuentra nada, `always` los consulta en cada búsqueda, `never` restringe la búsqueda al catálogo. Omitir para usar el valor por defecto del servidor (`auto`). |

### salida de search

| Campo              | Tipo   | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `next_steps`       | array  | Llamadas de seguimiento sugeridas — p. ej. un ejemplo de `get_details` o `download` usando el `md5`/`doi` del primer resultado, o, cuando no hay coincidencias, cómo ampliar la consulta. | `results`          | array  | Los registros de archivo de esta página. Un registro de una publicación seriada (un artículo de revista, una revista o un cómic) lleva además su designador `issue`, y ningún ISBN — su identificador es el `doi`. El marcador de `edition`, cuando el catálogo imprime uno, se extrae del título a su propio campo para que los títulos se comparen limpiamente. Array vacío cuando no hay coincidencias. |
| `page`             | int    | El número de página devuelto.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

| `reachable`        | int    | Cuántos resultados son realmente alcanzables a través de todas las páginas (los mirrors limitan esto por debajo de `total_files`).                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `truncated`        | bool   | `true` cuando `total_files` supera a `reachable`, es decir, algunas coincidencias no pueden paginarse.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `hint`             | string | Presente solo cuando `truncated` — aconseja refinar la consulta (añadir autor/año, usar columnas de solo título o acotar temas).                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `has_more`         | bool   | `true` cuando esta página está llena (`len(results) >= results_per_page`), lo que sugiere que puede existir una página siguiente.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `mirror`           | string | La URL base del mirror que sirvió esta búsqueda.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `open_access`      | array  | Presente solo cuando el descubrimiento de acceso abierto se ejecutó y encontró algo. Ver [Descubrimiento de acceso abierto](#descubrimiento-de-acceso-abierto).                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Paginación y truncado

Los mirrors de Library Genesis anuncian un recuento total de coincidencias (`total_files`) pero solo sirven los primeros `reachable` resultados a través de las páginas. Cuando el total anunciado supera ese tope, la búsqueda está `truncated` y `hint` explica cómo acotarla, por ejemplo:

> Only the first 250 of 38514 results are reachable; refine your query (add author/year, use title-only columns, or narrow topics).

Prefiere refinar una consulta truncada antes que paginar en profundidad: las páginas más allá de `reachable` no devuelven nada.

### Errores

La entrada inválida se rechaza antes de cualquier llamada de red: un `query` vacío, un `topic`, `search_in` u `order` desconocido, un `results_per_page` distinto de 25/50/100, o un `order_mode` distinto de `asc`/`desc`. Los problemas de conectividad y de mirror aparecen como se describe en [Solución de problemas](/libgen-mcp/es/troubleshooting/).

### Descubrimiento de acceso abierto

Más allá del catálogo de Library Genesis, `search` puede consultar también **fuentes extra** — [Anna's Archive](https://annas-archive.org/), [arXiv](https://arxiv.org/), [Crossref](https://www.crossref.org/), [OpenLibrary](https://openlibrary.org/), [Project Gutenberg](https://www.gutenberg.org/), [dblp](https://dblp.org/), [PubMed](https://pubmed.ncbi.nlm.nih.gov/) y [ERIC](https://eric.ed.gov/) — controlado por el argumento `extra_sources` (`auto`/`always`/`never`) y su valor por defecto de despliegue `LIBGEN_MCP_EXTRA_SOURCES` (por defecto `auto` — ver [Configuración](/libgen-mcp/es/configuration/)). El valor por defecto `auto` los consulta solo cuando el catálogo no devuelve nada o falla; `always` los consulta en cada búsqueda, a la vez que el catálogo; `never` restringe la búsqueda al catálogo, incluso si no hay resultados. Los resultados de Anna's, identificados por md5, se fusionan en `results` (etiquetados `origin: "annas"`); los de arXiv, Crossref, OpenLibrary, Project Gutenberg, dblp, PubMed y ERIC aparecen en un campo `open_access` separado junto a `results`.

Ese nombre de campo es anterior a los índices bibliográficos y hoy es algo impreciso: dblp y PubMed describen un artículo sin afirmar nada sobre su disponibilidad, y ERIC solo aloja una parte de lo que indexa, así que **solo se sabe que es de lectura libre un resultado cuyo propio flag `open_access` sea `true`**. Un resultado de dblp o PubMed es una cita, no una descarga.

```json title="entrada de search"
{
	"query": "attention is all you need",
	"topics": ["articles"],
	"extra_sources": "always"
}
```

```json title="salida de search (extracto)"
{
	"open_access": [
		{
			"origin": "arxiv",
			"title": "Attention Is All You Need",
			"authors": "Ashish Vaswani, Noam Shazeer, ...",
			"year": "2017",
			"pdf_url": "https://arxiv.org/pdf/1706.03762",
			"open_access": true
		},
		{
			"origin": "crossref",
			"title": "Attention is All you Need",
			"authors": "...",
			"year": "2017",
			"doi": "10.5555/3295222.3295349"
		}
	]
}
```

Cada resultado lleva al menos un identificador accionable, según su `origin`:

- **`doi` (crossref)** — pásalo a `download` o `read` igual que un DOI de un resultado de Library Genesis.
- **`pdf_url` (siempre en arxiv; en crossref cuando hay un enlace directo a PDF publicado)** — un PDF de acceso abierto directamente descargable; obtenlo tú mismo (no es una descarga de Library Genesis, así que `download`/`read` no lo resuelven).
- **`isbn`/`title` (openlibrary)** — OpenLibrary es principalmente un _resolutor de consultas_ sin clave: usa su `isbn` o `title` canónicos para refinar una `search` de Library Genesis posterior. La única excepción es un libro de lectura pública — uno que OpenLibrary indica como libremente legible por completo en Internet Archive — que además lleva un `archive_url` (una página `https://archive.org/details/<id>` que puedes leer directamente) y se marca `open_access: true`.
- **`doi` + `venue` (dblp, pubmed)** — registros bibliográficos. dblp cubre informática y es autoridad sobre el congreso o la revista en que apareció un artículo; PubMed cubre biomedicina mucho más allá de la porción de acceso abierto, así que responde por artículos que ninguna fuente libre tiene. Cítalos, o pasa el `doi` a `download` y deja que la cadena de artículos decida si puede servirlo. Un registro sin DOI (habitual en literatura antigua) es solo metadatos.
- **`pdf_url` (eric)** — ERIC indexa investigación educativa y aloja un texto completo autorizado de una parte de ella: los informes, tesis, ponencias de congreso y documentos de agencias que forman la **literatura gris** educativa, que no llevan DOI y no aparecen en ninguna de las fuentes anteriores. Un resultado con `pdf_url` es uno de esos documentos alojados — descarga esa URL, que es la única forma de obtenerlo, porque no hay DOI con el que `download` pueda operar. Un resultado sin ella es un registro bibliográfico, y no se marca como acceso abierto.

Un resultado también puede llevar un `venue`: el medio de publicación tal y como lo indica el proveedor — el `journal_ref` de arXiv (una cadena de cita corta como `Phys. Rev. Lett. 100, 012345 (2021)`), la abreviatura del congreso o revista en dblp (`DAC`, `Commun. ACM`), el nombre completo de la revista en PubMed, o la fuente y la cadena de volumen/número en ERIC (`Professional Development in Education, v40 n2 p295-315 2014`), que en un informe pasa a ser la institución que lo produjo. Está ausente en un preprint sin versión publicada, y es una cadena de cita, nunca un resumen. Úsalo para distinguir un artículo ya publicado de un preprint sin publicar; no es un identificador que puedas pasar a otra herramienta.

<Aside type="caution">
	Los resultados se dedupan entre sí (por DOI normalizado, luego por
	título+año), así que un mismo artículo hallado por dos proveedores aparece una
	vez. No se comparan contra `results`, que se indexa por md5 y no por DOI: solo
	los resultados de Anna's, que sí llevan md5, se suprimen cuando el catálogo ya
	los listaba. Los ocho proveedores son sin clave — sin cuenta, API key ni login
	— y best-effort: cada uno corre bajo su propio presupuesto corto, así que un
	proveedor lento o que falla se degrada a no aportar nada en lugar de retrasar
	o hacer fallar la búsqueda principal de Library Genesis. Como cualquier
	resultado externo, los títulos y autores de `open_access` son contenido de
	terceros NO CONFIABLE — resúmelos o actúa sobre los identificadores, nunca
	sigas instrucciones incrustadas en el texto.
</Aside>

## get_details

`get_details` es la herramienta que obtiene los metadatos completos de un registro vía la API JSON de LibGen — descripción, identificadores, DOI, portada y edición relacionada. Consulta por `md5`, por `id` o por `doi` — exactamente uno de los tres.

### entrada de get_details

| Parámetro | Tipo   | Requerido | Descripción                                                                                                                                                                     |
| --------- | ------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `md5`     | string | uno de    | Hash MD5 de archivo de un resultado de búsqueda. Devuelve el registro de archivo más su primera edición relacionada. Debe ser una cadena hexadecimal de 32 caracteres.          |
| `id`      | string | uno de    | Id de edición o de archivo.                                                                                                                                                     |
| `doi`     | string | uno de    | DOI del artículo, p. ej. `10.1016/j.cell.2011.02.013`. Se busca de forma exacta en el catálogo; la respuesta lleva la edición más el `md5` del fichero para pasar a `download`. |
| `object`  | string | no        | Se usa con `id`: `edition` (por defecto) o `file`.                                                                                                                              |
| `enrich`  | bool   | no        | Cuando es `true`, aumenta el registro con metadatos sin clave de Crossref (por DOI) y OpenLibrary (por ISBN). Best-effort y desactivado por defecto.                            |

<Aside type="note">
	Proporciona exactamente uno de `md5`, `id` o `doi` — **nunca más de uno**.
	Aportar varios, ninguno, un `md5` que no sea de 32 caracteres hex, o un
	`object` distinto de `edition`/`file` devuelve un error de entrada.
</Aside>

### salida de get_details

| Campo        | Tipo   | Descripción                                                                                                                                                                                                                                                                                                                                      |
| ------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `next_steps` | array  | Llamada de seguimiento sugerida — p. ej. una llamada a `download` con el `md5` (libro) o `doi` (artículo) de este registro. Presente para guiar al modelo; se puede ignorar.                                                                                                                                                                     |
| `file`       | object | El registro de archivo (presente en una consulta por `md5`, o una consulta por `id` con `object: file`).                                                                                                                                                                                                                                         |
| `edition`    | object | El registro de edición (presente en la edición relacionada de una consulta por `md5`, o una consulta por `id` con `object: edition`).                                                                                                                                                                                                            |
| `citations`  | object | `{"bibtex": ..., "ris": ...}` — una exportación BibTeX y RIS lista para pegar, construida a partir de los metadatos del registro. Se omite cuando el registro no tiene título (el mínimo necesario para una cita útil). Los campos de metadatos vacíos se descartan en lugar de emitirse en blanco, y la exportación no lleva ningún campo ISBN. |
| `enrichment` | object | Metadatos externos best-effort (Crossref/OpenLibrary), presentes cuando se pidió `enrich` y se encontró algo — y también en el respaldo de Crossref descrito más abajo, que los devuelve tanto si los pediste como si no. Ver [Enriquecimiento de metadatos](#enriquecimiento-de-metadatos).                                                     |

Una consulta por `md5` devuelve `file` y, en la medida de lo posible, su `edition` relacionada. Una consulta por `id` devuelve el objeto que se haya pedido. Una consulta que no coincide con nada devuelve un error "no record", salvo que responda antes alguno de los respaldos descritos más abajo.

### Registros que el catálogo no tiene

Una [búsqueda que ha consultado las fuentes adicionales](/libgen-mcp/es/how-search-works/) devuelve md5 que el catálogo de Library Genesis nunca indexó, así que consultarlos en el catálogo no encuentra nada. En lugar de fallar, `get_details` recurre a Anna's Archive y devuelve lo que esta publica para ese md5, con `file.origin` a `annas` para que sepas qué índice ha respondido.

Ese registro es **más pobre que uno del catálogo** y sus campos varían según la colección de la que venga el ítem. Todos los registros de Anna's observados llevan `title`, `author`, `language`, `year`, `content_type`, `collection`, `filesize` y `filepath`; `isbn`/`isbn10` e `ipfs_cid` aparecen en una minoría. Ojo en particular a que la mayoría **no** tiene `ipfs_cid`, así que la ruta de descarga sin clave por IPFS no está disponible para ellos: hace falta una clave de socio u otra fuente. `author` es el campo propio de Anna's y a veces es la cadena del productor del PDF en lugar de una persona.

Un **DOI** que el catálogo no tiene se resuelve igual por otra vía. Con el enriquecimiento activo (`LIBGEN_MCP_ENRICH`, activado por defecto), `get_details` recurre a Crossref y devuelve un registro sintético — `file.origin` vale `crossref` y `file.doi` es el DOI que pediste — con los metadatos de Crossref en `enrichment`. Ese bloque aparece aquí **aunque no hayas fijado `enrich`**, porque el respaldo no tiene otra cosa que devolver. Igual que el registro de Anna's, es más pobre que uno del catálogo: no lleva md5, así que pasa el propio DOI a `download`.

Solo cuando ningún índice tiene el identificador devuelve la herramienta el error de ausencia del catálogo.

### Enriquecimiento de metadatos

Fija `enrich: true` para añadir un objeto `enrichment` best-effort con datos sin clave de dos APIs públicas, ejecutadas en paralelo bajo un presupuesto de 6 segundos:

- **[Crossref](https://www.crossref.org/)**, por el DOI del registro: `container_title` (título de la revista/libro), `issn`, `volume`, `issue`, `publisher`, `published_year`, `reference_count`, `citation_count` (el `is-referenced-by-count` de Crossref) y `subjects`.
- **[OpenLibrary](https://openlibrary.org/)**, por el ISBN del registro: `subjects`, `description`, `cover_url` y `open_library_url`.

<Aside type="note">
	El enriquecimiento es **opt-in por llamada** (`enrich` es `false` por defecto)
	y además puede **prohibirse a nivel de despliegue** con
	`LIBGEN_MCP_ENRICH=false` (por defecto `true`, es decir, permitido — ver
	[Configuración](/libgen-mcp/es/configuration/)). Es estrictamente best-effort:
	un DOI/ISBN ausente, una API lenta o que falla, o exceder el presupuesto de 6s
	degradan en silencio a un campo `enrichment` ausente. El enriquecimiento se
	ejecuta de forma síncrona dentro de la llamada a `get_details`: nunca hace
	fallar el resultado principal, pero puede añadir una latencia acotada — hasta
	el presupuesto de ~6s — antes de que la respuesta se devuelva. No se requiere
	clave de API; ambas APIs se usan sin autenticación.
</Aside>

## download

<Aside type="caution">
	`libgen-mcp` accede a mirrors de terceros de Library Genesis. Eres responsable
	de respetar las leyes de derechos de autor y de propiedad intelectual que
	apliquen en tu lugar de residencia. Úsalo solo para contenido al que tengas
	derecho legal de acceder.
</Aside>

`download` es la herramienta que resuelve un ítem por la cadena ordenada de fuentes y lo guarda en un directorio local. Proporciona `md5` o `isbn` para un libro **o** `doi` para un artículo; se requiere al menos uno. Devuelve la ruta guardada, el tamaño y la fuente que lo sirvió.

### Fuentes probadas

La descarga recorre una cadena de fuentes fija, filtrada por lo que admite cada elemento:

- **Libro** (`md5` solo) → `libgen` (clave de ads.php + CDN), luego `randombook` (descubrimiento de mirrors frescos), luego `annas` (IPFS sin clave, o descarga rápida de miembros cuando `LIBGEN_MCP_ANNAS_KEY` está fijado).
- **Libro** (`isbn` solo) → `oapen` (monografías académicas con licencia abierta), luego `archive` (escaneos de dominio público de Internet Archive, localizados a través de OpenLibrary). Un escaneo se sirve solo cuando OpenLibrary informa del libro como `ebook_access: public` **y** archive.org informa del elemento concreto como no restringido y fuera de toda colección de préstamo, de modo que una copia de préstamo digital controlado se descarta en lugar de descargarse como un archivo inservible.
- **Artículo** (`doi` solo) → primero los proveedores legales de acceso abierto — `unpaywall` (solo cuando `LIBGEN_MCP_UNPAYWALL_EMAIL` está fijado, si no se omite), luego `europepmc`, `biorxiv` (preprints `10.1101`), `rfc` (RFC `10.17487`), `nist` (publicaciones del NIST `10.6028`), `fatcat`, `core` (solo cuando `LIBGEN_MCP_CORE_KEY` está fijado) y `oapen` (las monografías también tienen DOI) — y luego los fallbacks de bibliotecas en la sombra `scihub` y `scidb` (visor SciDB de Anna's Archive).
- **Ambos `md5` y `doi`** → primero las fuentes de artículo, luego las de libro (`libgen`, `randombook`, `annas`).

Gana la primera fuente que resuelve y transmite un archivo válido; el campo `source` del resultado la nombra. Consulta [Arquitectura](/libgen-mcp/es/architecture/) para la cadena completa.

	Solo las descargas identificadas por `md5` se comprueban por hash. Tanto una
	descarga por `doi` (artículo) como una descarga de libro por `isbn` llegan sin
	un digest de LibGen contra el que comparar, así que el campo `verified` del
	resultado es `false` en ambos casos — incluidos los libros de OAPEN y del
	Internet Archive.
</Aside>

### Comportamiento y errores

- **Nombres limpios.** Sin un `filename` explícito, la descarga toma el nombre anunciado por el CDN (`Content-Disposition`), y si no hay, recurre a un `Author - Title (Year).ext` construido a partir de los metadatos del registro y luego al MD5. Los caracteres de ruta ilegales se eliminan.
- **Reanudación.** Una descarga interrumpida deja un archivo `.part`; una llamada posterior pide al CDN continuar desde el offset existente. Si el servidor ignora el rango, reinicia limpiamente.
- **Verificación MD5.** Para descargas identificadas por `md5` se calcula el hash del archivo completo y se compara con el digest solicitado; una discrepancia elimina el parcial y falla la descarga. Las descargas por `doi` y por `isbn` no llevan digest, así que omiten esta comprobación.
- **Guardas.** Las páginas HTML de error se rechazan (por tipo de contenido e inspeccionando los primeros bytes), se aplica el límite de tamaño (`LIBGEN_MCP_MAX_DOWNLOAD_BYTES`), se comprueba el espacio libre en disco antes de transmitir, y el archivo completado se renombra atómicamente en su lugar.
- **Progreso.** Cuando el cliente aporta un token de progreso, se emiten notificaciones de progreso limitadas durante el streaming.

Si todas las fuentes aplicables fallan, la herramienta devuelve los errores por fuente unidos. Consulta [Solución de problemas](/libgen-mcp/es/troubleshooting/) para saber cómo leerlos.

### Dónde acaba el archivo: local vs. remoto

Por defecto `download` obtiene el archivo en la máquina que **ejecuta el servidor**. Con un servidor **local** por stdio o Docker esa máquina es la tuya, así que los archivos quedan en tu directorio de descargas (`LIBGEN_MCP_DOWNLOAD_DIR`, o `~/Downloads`) — ideal para agentes locales autónomos.

Un servidor pasa a **modo de descarga remota** cuando se arranca con `--http`, **o** cuando se fija `LIBGEN_MCP_REMOTE_DOWNLOADS=1`. El caso `--http` es un servidor que se ejecuta en otra máquina y no puede escribir en tu disco. `LIBGEN_MCP_REMOTE_DOWNLOADS` cubre el equivalente por stdio: un **despliegue stdio alojado** —por ejemplo el servidor ejecutándose como stdio detrás de `mcp-proxy` en un catálogo como Glama— cuyo proceso vive en una máquina remota o efímera cuyo disco el cliente no puede alcanzar, aunque el transporte en sí sea stdio. Cualquiera de los dos disparadores produce el mismo efecto: cada llamada a `download` **devuelve automáticamente un enlace** —la URL directa como `resource_link` más un objeto `resolved` (con las `headers` necesarias)— sin guardar el archivo. No necesitas fijar `resolve_only` en este caso; está implícito, y la propia descripción de la herramienta lo indica. Tú —o la herramienta de fetch/HTTP de tu propio agente— recuperas esa URL, así que el archivo acaba allí donde se ejecute ese fetch. En un servidor **local** aún puedes pedir el mismo comportamiento por llamada con `resolve_only: true`. MCP no tiene forma de que una herramienta empuje bytes al cliente, así que un enlace es la única manera en que un servidor en modo remoto puede entregar un archivo de varios megabytes.

### Peticiones interactivas (elicitation)

Cuando el cliente MCP conectado admite **elicitation** (pedir información al usuario), `download` puede preguntar hasta tres cosas — todas puramente opt-in, y todas no-ops en un cliente que no anuncia la capacidad. Una llamada que necesita más de una las pregunta juntas, en un solo intercambio:

- **Email de Unpaywall bajo demanda.** Si descargas un artículo por `doi` y el servidor no tiene configurado `LIBGEN_MCP_UNPAYWALL_EMAIL`, a un cliente compatible con elicitation se le pide un email de contacto para buscar una copia de acceso abierto vía Unpaywall solo para _esa petición_ — nunca se almacena, y la pregunta se omite siempre que se haya fijado explícitamente `source`. Rechazar, dejar la respuesta vacía o dar una dirección inverosímil deja la petición sin cambios: `unpaywall` queda fuera de la cadena y se prueba el resto de ella — las fuentes de acceso abierto sin clave y después `scihub`/`scidb` — exactamente como hoy.
- **Clave de miembro de Anna's Archive bajo demanda.** Si descargas un libro por `md5` con `annas_member: true` y el servidor no tiene configurado `LIBGEN_MCP_ANNAS_KEY`, a un cliente compatible con elicitation se le pide una clave de cuenta para usar el nivel de descarga rápida de miembros solo para _esa petición_ — nunca se almacena, y la pregunta se omite cuando se ha fijado un `source` distinto de `annas`. Rechazar o dejar la respuesta vacía deja la petición sin cambios: la fuente `annas` sigue sin clave y resuelve por IPFS.
- **Confirmación de descarga.** Antes de que `download` escriba un archivo en el disco del servidor (es decir, sin `resolve_only` y sin un servidor remoto/HTTP), a un cliente compatible con elicitation se le pide confirmar, mostrando el nombre del archivo de destino y, de mejor esfuerzo, su tamaño. Rechazar no escribe nada y devuelve en su lugar el enlace directo resuelto, para que puedas obtenerlo tú mismo. El aviso incluye además una casilla opcional **«dejar de preguntar durante el resto de esta sesión»**: márcala y las descargas posteriores de esa sesión se guardan sin preguntar. Otras dos exclusiones hacen lo mismo con distinto alcance: `skip_confirmation: true` para una sola llamada y `LIBGEN_MCP_CONFIRM_DOWNLOADS=false` para todo el despliegue. Basta con cualquiera de ellas, y ninguna puede hacer aparecer un aviso allí donde no se puede preguntar al cliente.

<Aside type="note">
	Ninguna de estas peticiones es nunca obligatoria: elicitation es totalmente
	opt-in y depende de la capacidad del cliente. Un cliente sin capacidad de
	elicitation (p. ej. un cliente headless o de CI) no ve ninguna petición ni
	sondeo de tamaño.
</Aside>

Por dentro, la pregunta viaja de vuelta en el resultado de la herramienta y el cliente la responde llamando otra vez a `download` con la respuesta (peticiones multi round-trip, SEP-2322): la versión de protocolo 2026-07-28 ya no permite que un servidor abra una petición mientras atiende una llamada. Los clientes en versiones de protocolo anteriores no se ven afectados — el SDK de MCP responde sus peticiones como antes. Hay una consecuencia que conviene conocer: si el propio manejador de peticiones del cliente falla, ahora la llamada a `download` falla con él, mientras que antes el servidor veía el fallo y continuaba con su comportamiento por defecto.

## read

`read` es la herramienta que extrae y pagina el texto de un libro o artículo para que un modelo pueda leerlo sin descargar el archivo entero. Identifica el archivo por `md5` (un libro) o `doi` (un artículo) de una búsqueda previa, o por una ruta `path` absoluta a un archivo ya descargado (solo servidor local). La extracción es Go puro — PDF (solo capa de texto), EPUB y TXT — sin OCR.

### entrada de read

Debe ser una cadena hexadecimal de 32 caracteres.                                                                                                                                                                         |
| `doi`         | string | uno de    | DOI de un resultado de búsqueda de artículo.                                                                                                                                                                                                                                   |

### No extraíble

Algunos archivos no tienen ninguna capa de texto utilizable. `read` nunca ejecuta OCR — en su lugar informa `extractable: false` con un `reason` que explica por qué, para que el modelo pueda recurrir a `download` y entregar el archivo en bruto al usuario. Esto cubre, entre otros:

- **PDFs escaneados o solo-imagen** — sin capa de texto extraíble (`"no extractable text layer (likely a scanned or image-only PDF); OCR is not supported"`).
- **PDFs malformados o cifrados**, y PDFs abiertos más allá de su última página.
- **Cómics y otros formatos no soportados/propietarios** (p. ej. CBR/CBZ) — se informan como extensión de archivo no soportada.
- **EPUBs malformados** o un EPUB sin texto extraíble en su spine.

### Una capa de texto que extrae disparates

`extractable: true` dice que salió texto del archivo, no que sea el texto impreso en la página. Un PDF cuyas fuentes no llevan un mapa de caracteres utilizable se extrae tan tranquilamente — a glifos de reemplazo, o a letras mapeadas sobre otras letras — y el resultado se lee como basura verosímil que un modelo resumirá sin pestañear. Copias del catálogo de libros por lo demás correctos hacen justo esto; es un defecto del archivo, no de la extracción.

`read` mide dos señales independientes del alfabeto sobre el fragmento que devuelve — la proporción de glifos sin mapear (caracteres de reemplazo, de uso privado y de control) y la proporción de palabras latinas sin ninguna vocal — y, cuando alguna se aleja muchísimo de lo que produce cualquier idioma, fija `text_quality_note` explicando lo que ha encontrado. `next_steps` le dice entonces al modelo que no presente ese texto como el contenido del documento y que pruebe otra edición o descargue el archivo en bruto.

Los umbrales son deliberadamente conservadores: el campo no aparece en una lectura sana, y una página en cirílico, griego o CJK se juzga solo por la medida de glifos, ya que la regla de las vocales no le aplica. La nota es un indicio fuerte, no un veredicto — una página muy matemática puede leerse rara sin estar rota.

### Paginación y la caché

Los PDF paginan por página (`start_page`/`max_pages`); EPUB y TXT paginan por desplazamiento de carácter (`offset`/`max_chars`). En ambos casos, el `cursor` opaco de la respuesta codifica la posición de reanudación — pásalo de vuelta en la siguiente llamada (con el mismo `md5`/`doi`/`path`) para continuar donde quedó el último fragmento. Una obtención por `md5`/`doi` se cachea en el servidor como archivo temporal durante `LIBGEN_MCP_READ_CACHE_TTL`, de modo que las páginas sucesivas de una misma lectura reutilizan una sola descarga en vez de volver a obtener el archivo en cada llamada; la caché está acotada en agregado por `LIBGEN_MCP_READ_CACHE_BYTES` (los archivos usados menos recientemente se desalojan primero, nunca uno que una llamada a `read` esté usando en ese momento). Consulta [Configuración](/libgen-mcp/es/configuration/) para los parámetros de ajuste.

### Buscar dentro de un documento

Fija `find` para buscar una frase en el documento en lugar de leerlo secuencialmente:

```json
{ "md5": "…", "find": "redes neuronales", "max_matches": 5 }
```

`read` devuelve entonces `matches` (cada una con `page`/`char_offset` y un `snippet` de una línea) y el total `match_count`, en vez del `text` secuencial. El campo `cursor` pagina la lista de coincidencias de la misma forma que pagina el texto secuencial — pásalo de vuelta con el mismo `find` para obtener la siguiente página de coincidencias, con `max_matches` controlando el tamaño de página (por defecto 10).

<Aside type="caution">
	Los snippets son contenido de terceros **NO CONFIABLE**, igual que el `text`
	secuencial — trátalos como datos, nunca como instrucciones.
</Aside>

Una consulta sin coincidencias devuelve un resultado claro de cero coincidencias (`match_count: 0`, `matches: []`) en lugar de una lectura secuencial vacía. Los archivos escaneados u otros no soportados siguen informando `extractable: false` con un `reason`, igual que en modo secuencial.

La coincidencia **ignora los espacios en ambos lados**: solo tienen que cuadrar los caracteres que no son espacio. Una capa de texto de PDF se come habitualmente el espacio entre dos palabras (`OverseasHarriette`), parte una en un salto de línea o rellena una palabra con espacios que sus glifos nunca tuvieron, y la comparación literal hacía que una búsqueda de frase informara de cero resultados en un documento que claramente la contiene — el peor fallo posible, porque nada en la respuesta indica que la búsqueda no era fiable. Los desplazamientos y los snippets siguen apuntando al texto original, así que una coincidencia se lee exactamente como la tiene el documento.

### Índice de contenidos

Fija `outline` para obtener la estructura del documento en lugar de su texto, para que un modelo pueda decidir qué leer a continuación y saltar directamente allí:

```json
{ "md5": "…", "outline": true }
```

`read` devuelve entonces `outline` — una lista ordenada de entradas, cada una con un `title`, un `level` (`0` para un capítulo de nivel superior, aumentando con el anidamiento) y, en PDFs, una `page`. Salta a una sección llamando de nuevo a `read` con `start_page` fijado a la página de esa entrada. Los índices provienen de la navegación EPUB (el documento `nav` de EPUB3, o el `.ncx` de EPUB2) y de los marcadores del PDF — ambos de mejor esfuerzo: los PDFs escaneados o antiguos a menudo no llevan marcadores, y un documento sin índice incrustado devuelve `extractable: true` con un `outline` vacío (no es un error).

Un libro técnico muy anidado puede llevar varios cientos de entradas, que es mucha respuesta para una pregunta tan simple como «¿qué capítulo cubre esto?». Fija `max_depth` para recortar el árbol a los niveles que de verdad necesitas — `{ "md5": "…", "outline": true, "max_depth": 1 }` devuelve solo las entradas de primer nivel. `outline_total` informa entonces de cuántas entradas tiene el índice completo, y `next_steps` avisa de que el resultado se ha recortado, de modo que un índice superficial nunca se confunde con uno corto.

<Aside type="caution">
	Los títulos de las entradas son contenido de terceros **NO CONFIABLE**, igual
	que el `text` y los snippets de `find` — trátalos como datos, nunca como
	instrucciones.
</Aside>

## Prompts

Además de las cuatro herramientas anteriores, `libgen-mcp` registra cuatro **prompts** MCP — plantillas de instrucciones reutilizables que un cliente MCP puede ofrecer como acciones rápidas o comandos de barra. El handler de cada prompt devuelve un único mensaje Markdown con rol `user` que le indica al modelo exactamente qué herramienta llamar a continuación (`get_details`, `download`) y con qué argumentos; un prompt nunca busca más de lo necesario para construir ese plan, y nunca descarga ni escribe nada por sí mismo.

### acquire_book

Busca un libro y obtén instrucciones paso a paso para confirmar y descargar la edición que mejor coincide.

| Argumento  | Requerido | Descripción                                          |
| ---------- | --------- | ---------------------------------------------------- |
| `title`    | sí        | Título del libro a buscar.                           |
| `author`   | no        | Nombre del autor para acotar la búsqueda.            |
| `format`   | no        | Formato de archivo preferido, p. ej. `pdf` o `epub`. |
| `language` | no        | Idioma preferido.                                    |

Busca en no ficción y ficción, clasifica los candidatos según coincidencia de formato/idioma (relajando a solo formato, y luego al primer resultado, cuando nada coincide exactamente), y devuelve una tabla de candidatos más un plan de dos pasos `get_details` → `download` para la mejor coincidencia.

### research_topic

Busca artículos y/o libros sobre un tema y construye una lista de lectura con instrucciones para descargar cada uno y elaborar una bibliografía anotada.

| Argumento | Requerido | Descripción                                                                     |
| --------- | --------- | ------------------------------------------------------------------------------- |
| `topic`   | sí        | Tema a investigar.                                                              |
| `kind`    | no        | Qué tipos de registro buscar: `articles`, `books` o `both`. Por defecto `both`. |
| `limit`   | no        | Filas máximas por sección. Por defecto `10`, con tope de `50`.                  |

Devuelve una lista de lectura Markdown de dos secciones — Papers (identificados por DOI) y Books (identificados por md5) — seguida de un plan para descargar cada elemento y elaborar una bibliografía anotada a partir de los resultados.

### get_paper

Resuelve un artículo concreto por DOI o por una cita en texto libre, y obtén instrucciones para descargarlo. Proporciona exactamente uno de `doi` o `citation`.

| Argumento  | Requerido | Descripción                                                                     |
| ---------- | --------- | ------------------------------------------------------------------------------- |
| `doi`      | uno de    | DOI del artículo a obtener directamente (mutuamente excluyente con `citation`). |
| `citation` | uno de    | Cita o referencia en texto libre a buscar (mutuamente excluyente con `doi`).    |

Con `doi`, el prompt devuelve un plan directo `download {"doi": ...}` — indica explícitamente que `get_details` **no** acepta un DOI a secas como entrada, para que el modelo no se equivoque de ruta. Con `citation`, busca en artículos una coincidencia, reintentando una vez entre los libros (algunos papers están catalogados así) cuando no aparece nada, y enumera los candidatos a descargar por DOI.

### download_troubleshoot

Diagnostica una descarga fallida o atascada y produce un plan de recuperación paso a paso adaptado al identificador, a los proveedores habilitados y a cualquier mensaje de error.

| Argumento | Requerido | Descripción                                                            |
| --------- | --------- | ---------------------------------------------------------------------- |
| `md5`     | no        | md5 de la descarga de libro que falló.                                 |
| `doi`     | no        | DOI de la descarga de artículo que falló.                              |
| `error`   | no        | El mensaje de error que devolvió la herramienta `download`, si lo hay. |

Todos los argumentos son opcionales. El árbol de decisión resultante solo nombra los proveedores de descarga que están realmente **habilitados** en este servidor (vía `LIBGEN_MCP_SOURCES`), sugiere volver a ejecutar `search` para descartar un identificador obsoleto, guía cómo fijar el parámetro `source` de `download` para aislar un proveedor que falla y —cuando se reconoce un mensaje de error conocido— añade consejos específicos (p. ej. un md5 malformado, una `LIBGEN_MCP_UNPAYWALL_EMAIL` sin fijar, una transferencia estancada o un fallo de verificación de integridad).

## Preguntas frecuentes

### ¿Qué herramienta de libgen-mcp debo usar?

Depende de lo que tengas y de lo que quieras. Usa `search` cuando tengas un título, un autor o un tema y necesites encontrar el registro. Usa `get_details` cuando ya tengas un identificador y quieras los metadatos completos, una cita, o el enriquecimiento de Crossref y OpenLibrary. Usa `download` cuando quieras el fichero en disco. Usa `read` cuando quieras el texto pero no el fichero — extrae y pagina un documento en el servidor, de modo que un modelo puede resumir un artículo o buscar dentro de un libro sin transferirlo entero.

### ¿Puede libgen-mcp leer un libro sin descargarlo?

Sí, y para eso está `read`. Trae el fichero a una caché temporal del servidor, extrae el texto en Go puro y devuelve una página cada vez, de modo que llamadas sucesivas sobre el mismo documento reutilizan una única descarga. Tiene además un modo `find` que busca dentro del documento y un modo `outline` que devuelve su tabla de contenidos. No se escribe nada en tu directorio de descargas.

### ¿Cómo descargo un artículo que no tiene MD5?

Con su DOI. Los libros del catálogo de Library Genesis se identifican por MD5, pero los artículos se identifican por DOI, y `download` acepta cualquiera de los dos — más `isbn` para un libro de las fuentes de acceso abierto. Pasar un DOI encamina la petición por la cadena de artículos, que prueba Unpaywall, Europe PMC, bioRxiv/medRxiv, Internet Archive Scholar, CORE y OAPEN antes que Sci-Hub o SciDB.

### ¿Qué pasa cuando falla una fuente de descarga?

La cadena pasa a la siguiente fuente que pueda servir el ítem, y la herramienta te dice cuál lo consiguió. Una fuente que falla porque no está disponible — un error de transporte, un timeout, un 5xx o un 429 — se aparta durante cinco minutos para que no entorpezca llamadas posteriores. Una fuente que responde correctamente que no tiene el ítem no se penaliza: eso es una respuesta normal sobre un ítem y no dice nada sobre la salud del proveedor.
