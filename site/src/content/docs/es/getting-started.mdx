`libgen-mcp` se instala de cuatro formas: desde npm como [`@jmrp.io/libgen-mcp`](https://www.npmjs.com/package/@jmrp.io/libgen-mcp), como binario estático precompilado desde la página de releases de GitHub, como imagen Docker (`ghcr.io/jmrplens/libgen-mcp`) o con `go install`. No necesita cuenta, clave de API ni token. En cuanto queda registrado en un cliente MCP — Claude Code, Claude Desktop, Cursor o VS Code — sus cuatro herramientas (`search`, `get_details`, `download`, `read`) están disponibles de inmediato.

## Instalación

Si ya tienes Node 18 o posterior, **npm** es el camino más corto — un solo comando, y tu cliente MCP puede lanzar el servidor con `npx` sin instalar nada. Si no, el **binario precompilado** es un único ejecutable estático sin nada más que instalar: sin toolchain de Go, sin Docker, sin runtime. Docker y `go install` se ofrecen como alternativas.

El paquete es un lanzador ligero sobre los mismos binarios precompilados que sirve la página de releases: el ejecutable viaja dentro de un paquete por plataforma que npm desempaqueta solo cuando coinciden su `os` y su `cpu`, así que no se compila nada y no se ejecuta ningún script en la instalación. ## Configurar un cliente MCP

Apunta tu cliente al binario. El comando es `libgen-mcp` (o la ruta absoluta al binario `server` si mantuviste el nombre por defecto de `go install`). Sobre stdio no hacen falta argumentos adicionales.

### Claude Code

Añade el servidor al `.mcp.json` de tu proyecto (o ejecuta `claude mcp add`):

```json
{
	"mcpServers": {
		"libgen": {
			"command": "libgen-mcp"
		}
	}
}
```

### Claude Desktop

La vía más sencilla es la extensión **`.mcpb`** de un clic de la [última release](https://github.com/jmrplens/libgen-mcp/releases/latest) (universal para macOS + Windows, sin Docker): descárgala, ábrela con Claude Desktop y confirma los ajustes.

Para configurarlo a mano, edita `claude_desktop_config.json` (`~/Library/Application Support/Claude/` en macOS, `%APPDATA%\Claude\` en Windows) y añade el mismo bloque `mcpServers`, luego reinicia Claude Desktop:

```json
{
	"mcpServers": {
		"libgen": {
			"command": "/absolute/path/to/libgen-mcp",
			"env": {
				"LIBGEN_MCP_DOWNLOAD_DIR": "/absolute/path/to/downloads"
			}
		}
	}
}
```

<Aside type="caution">
	Los clientes de escritorio no heredan el `PATH` de tu shell, así que usa una
	ruta `command` absoluta.
</Aside>

### VS Code

El soporte MCP de VS Code (o las extensiones Continue / Cline) lee un `mcp.json` con la misma forma. En el formato propio de VS Code:

```json
{
	"servers": {
		"libgen": {
			"command": "libgen-mcp",
			"type": "stdio"
		}
	}
}
```

### Endpoint hospedado (sin instalar nada)

Hay una instancia pública en **`https://mcp.jmrp.io/libgen`**. No necesita cuenta, ni clave, ni ningún proceso local: apunta ahí cualquier cliente MCP capaz de hablar HTTP:

```json
{
	"mcpServers": {
		"libgen": { "type": "http", "url": "https://mcp.jmrp.io/libgen" }
	}
}
```

Es la forma más rápida de probar el servidor. Ejecutarlo **en local** — con Docker o con un binario, más arriba — o a través de [Smithery](https://smithery.ai/servers/@jmrp/libgen-mcp) sigue siendo la mejor forma de usarlo a diario, por dos razones concretas y no como advertencia de rigor:

- **Tus consultas pasan por la máquina de otra persona.** En local, lo que buscas no sale de tu ordenador. La instancia hospedada no guarda nada, pero "no guarda nada" es una promesa; "no se envió nunca" es un hecho.
- **`download` no puede escribir en tu disco desde un servidor remoto**, así que devuelve un enlace (un `resource_link` más un objeto `resolved`) en lugar de guardar un fichero. Eso es inherente al MCP remoto, no una limitación de este endpoint — ver [Dónde acaba el fichero](/libgen-mcp/es/tools/#dónde-acaba-el-archivo-local-vs-remoto).

El endpoint habla el mismo HTTP en streaming sin estado que se describe más abajo: `POST` lleva el protocolo, `GET` sobre el propio endpoint responde `405` a propósito — una ruta que el servidor no sirve responde `404` — y `https://mcp.jmrp.io/libgen/health` responde `{"status":"ok","version":"…","commit":"…","started_at":"…","uptime_seconds":…}`. Su versión sigue las releases de este repositorio, así que puede ir brevemente por detrás de una etiqueta recién publicada.

Es uno de los servidores listados en **[mcp.jmrp.io](https://mcp.jmrp.io/)**, un directorio de los servidores MCP que mantiene el autor, cada uno accesible en su propio endpoint bajo el mismo dominio; [`servers.json`](https://mcp.jmrp.io/servers.json) es esa misma lista para clientes automáticos.

### Remoto (HTTP en streaming)

Para ejecutar el servidor de forma centralizada y conectarte por HTTP en lugar de stdio, inícialo con una dirección y apunta los clientes con capacidad HTTP hacia él:

```bash
libgen-mcp --http :8080
```

En modo HTTP el servidor expone además un endpoint `GET /health` de disponibilidad que devuelve `200` mientras está sirviendo, cómodo para las comprobaciones de salud de contenedores y balanceadores de carga.

En modo HTTP el servidor publica además una **server card** en `GET /server-card` — la ubicación a la que la movió la extensión `ext-server-card`, servida como `application/mcp-server-card+json` — y, con los mismos bytes, en la ruta heredada `GET /.well-known/mcp/server-card.json`, que se mantiene porque los escáneres ya la piden ahí. Lleva `serverInfo`, las `capabilities` que negocia el handshake, un bloque `authentication` (este servidor no pide ninguna) y los listados completos de `tools` y `prompts`, de modo que un directorio o un escáner puede leer toda la superficie — los cuatro prompts incluidos — sin abrir una sesión MCP. Se sirve sin autenticación, responde al preflight CORS y lleva `Access-Control-Allow-Origin: *` para que también pueda leerla un directorio que corra en el navegador, y no le afecta el `405` que el modo sin estado devuelve en el endpoint MCP.

El transporte es **sin estado por defecto**: no hay `Mcp-Session-Id`, cada POST es una petición completa y `GET`/`DELETE` sobre el endpoint MCP devuelven `405` (`/health` no se ve afectado). Es lo que la versión `2026-07-28` del protocolo MCP exige sobre HTTP, y permite poner cualquier número de réplicas detrás de un balanceador normal, sin enrutado pegajoso. Otras dos opciones ajustan el transporte — `--json-response` devuelve `application/json` en lugar de SSE, y `--max-request-body-bytes` estrecha el límite de 4 MiB del cuerpo:

```bash
libgen-mcp --http :8080 --json-response --max-request-body-bytes 1048576
```

Esas rutas — el endpoint MCP, `/health` y las dos rutas de la card — son toda la superficie HTTP. **Cualquier otra ruta responde `404`**, con un cuerpo JSON que nombra el endpoint que se debería haber pedido; un `405` significa ya solo lo que dice, que se llegó al endpoint MCP con el método equivocado. Si un proxy inverso reenvía su prefijo a este servidor en lugar de quitarlo, monta todo el conjunto bajo ese prefijo con `--http-path`:

```bash
libgen-mcp --http :8080 --http-path /libgen
```

El endpoint pasa a ser `POST /libgen`, la sonda `GET /libgen/health`, y las cards cuelgan también de `/libgen`; `libgen`, `/libgen` y `/libgen/` significan el mismo montaje, mientras que un valor con query, fragmento, segmento `..` o escapes porcentuales se rechaza al arrancar. Toda respuesta — incluidos el `404` y el `405` — lleva `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` y `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`. La card sobrescribe la cabecera de caché con su propia duración de una hora. `Strict-Transport-Security` se les une solo cuando este proceso termina TLS él mismo (`--tls-cert`, más abajo); detrás de un proxy que lo termine, es el proxy quien la envía.

Si algún cliente tuyo todavía necesita el transporte con sesiones anterior, pasa `--stateless=false`; entonces negocia la versión `2025-11-25` del protocolo MCP o anterior. Consulta [Arquitectura](/libgen-mcp/es/architecture/#modo-sin-estado) para lo demás que cambia, incluida la nota sobre la elicitación.

Como un servidor HTTP atiende a clientes en cuyo disco no puede escribir, `download` devuelve un enlace (un `resource_link` más un objeto `resolved`) en lugar de guardar un fichero — en este modo no hace falta que fijes `resolve_only`. Consulta [Herramientas](/libgen-mcp/es/tools/#dónde-acaba-el-archivo-local-vs-remoto) para el detalle.

<Aside type="note">
	Alojar en su lugar un servidor **stdio** — por ejemplo detrás de `mcp-proxy`
	en un catálogo como Glama — también lo coloca en una máquina remota o efímera,
	solo que sin un listener HTTP. Fija `LIBGEN_MCP_REMOTE_DOWNLOADS=1` para poner
	a ese servidor stdio en el mismo modo de descarga remota que `--http` obtiene
	automáticamente.
</Aside>

#### Detrás de un proxy en la misma máquina: un socket unix

Si lo único que habla con este servidor es un proxy inverso en el mismo host, `--http` acepta también una ruta del sistema de archivos y abre ahí un socket unix en lugar de un puerto:

```bash
libgen-mcp --http /run/mcp-libgen.sock
```

La regla es que un valor que contiene `/` es una ruta: `/run/mcp-libgen.sock` y `./mcp.sock` son sockets, mientras que `:8080`, `127.0.0.1:8080` y — a propósito — un `mcp.sock` pelado son direcciones, porque un nombre pelado no se distingue de un nombre de host. Prefiérelo a TLS para un proxy en la misma máquina: no cifra el salto, lo elimina. No hay puente que espiar, ni salto por `docker-proxy`, ni puerto que otro proceso local pueda alcanzar, ni certificado que emitir o rotar.

El socket se crea con `0660` — propietario y grupo, nada más —, así que el proxy llega compartiendo el grupo y no por ser cualquier cuenta local; `--http-socket-mode 0600` (o cualquier otro modo octal) lo cambia. nginx apunta un upstream directamente a la ruta:

```nginx
upstream libgen {
    server unix:/run/mcp-libgen.sock;
}

server {
    listen 443 ssl;
    server_name mcp.example.org;

    location / {
        proxy_pass         http://libgen;
        proxy_http_version 1.1;
        proxy_buffering    off;   # la respuesta del POST es un flujo SSE real
        proxy_read_timeout 1h;    # las descargas emiten progreso durante minutos
    }
}
```

Con Docker, los dos contenedores comparten el directorio del socket y no publican nada:

```yaml
services:
  libgen-mcp:
    image: ghcr.io/jmrplens/libgen-mcp:latest
    command: ["--http", "/run/mcp/libgen.sock"]
    user: "10001:10001"
    volumes:
      - ./run:/run/mcp # aquí vive el socket; no se publica ningún puerto
  proxy:
    image: nginx:1.29-alpine
    ports:
      - "443:443"
    volumes:
      - ./run:/run/mcp
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
```

Los procesos worker del proxy tienen que correr en el grupo del socket (aquí el GID `10001`) para poder abrir un socket `0660` — en nginx eso es el segundo argumento de la directiva `user`, `user nginx 10001;`, porque nginx reinicializa sus grupos al soltar privilegios.

<Aside type="caution">
	Un socket unix sigue siendo un valor de `--http` no vacío, así que `download`
	se queda en modo remoto (solo enlaces). Es lo correcto — un socket detrás de
	un proxy atiende a clientes que no están en esta máquina —, pero "socket unix"
	se lee como "local" y no lo es.
</Aside>

#### Terminar TLS en este proceso

Cuando el proxy está en **otro** host sí hay un segmento de red que tiene que existir, y este servidor puede terminar TLS él mismo:

```bash
libgen-mcp --http 0.0.0.0:8443 --tls-cert /etc/ssl/mcp.crt --tls-key /etc/ssl/mcp.key
```

Las dos opciones o ninguna — un certificado sin clave aborta el arranque, igual que un archivo que no se puede leer o una clave que no case con su certificado, porque la pareja se carga al arrancar y no en el primer handshake. El listener exige TLS 1.2 o superior y negocia HTTP/2 con los clientes que lo ofrecen. Entonces toda respuesta lleva `Strict-Transport-Security: max-age=31536000; includeSubDomains`, que solo el endpoint que realmente terminó la conexión está en posición de afirmar.

Si el certificado viene de una CA privada, hay que apuntar el proxy de delante a esa CA — en nginx, `proxy_ssl_verify on;` **junto con** `proxy_ssl_trusted_certificate /etc/nginx/ca.pem;` y un `proxy_ssl_name` que case con el certificado. nginx no verifica por defecto los certificados de los upstream, así que dejar `proxy_ssl_verify` desactivado oculta una cadena mala, y activarlo sin el archivo de la CA hace fallar todas las peticiones.

Consulta [Configuración](/libgen-mcp/es/configuration/) para las variables de entorno que puedes fijar en cualquiera de estos casos, y [Arquitectura](/libgen-mcp/es/architecture/) para saber cómo funcionan los transportes.

## Tu primera búsqueda

<LegalNotice />

Cuando el cliente muestre `libgen` como conectado, pídele que busque. Una petición como:

> Busca "the go programming language" en no ficción, 25 resultados.

acciona la herramienta `search` con más o menos estos argumentos:

```json
{
	"query": "the go programming language",
	"topics": ["nonfiction"],
	"results_per_page": 25
}
```

Cada resultado incluye un `md5` (para libros) o un `doi` (para artículos). Pasa un `md5` a `get_details` para obtener los metadatos completos, y luego a `download` para descargar el archivo — o pasa un `doi` directamente a `download` para un artículo. `get_details` también devuelve un campo `citations` (`bibtex`/`ris`) que puedes pegar directamente en un gestor de referencias, y acepta un `enrich: true` opt-in para añadir metadatos best-effort de Crossref/OpenLibrary. Consulta [Herramientas](/libgen-mcp/es/tools/) para ver todas las formas de entrada y salida.

## Leer y resumir

No hace falta descargar un archivo solo para ver qué contiene: `read` extrae y pagina directamente el texto de un libro o artículo. Una petición como:

> Busca el artículo "Attention Is All You Need", lee su primera página y resume de qué trata.

hace que el modelo busque y luego llame a `read` con el DOI (o el `md5` de un libro) del resultado:

```json
{
	"doi": "10.48550/arXiv.1706.03762",
	"max_pages": 1
}
```

El campo `text` de la respuesta contiene el primer fragmento extraído — hasta `LIBGEN_MCP_READ_MAX_CHARS` caracteres, o `LIBGEN_MCP_READ_DEFAULT_PAGES` páginas de PDF, según aplique al formato — más `has_more`/`cursor` para seguir paginando, y `extractable`/`reason` cuando el archivo no tiene una capa de texto utilizable (un PDF escaneado, por ejemplo — `read` nunca ejecuta OCR).

<Aside type="caution">
	Trata `text` como **contenido no confiable que hay que resumir, no como
	instrucciones que seguir**; la propia `next_steps` de la herramienta lo indica
	en cada llamada.
</Aside>

Consulta [Herramientas](/libgen-mcp/es/tools/#read) para la referencia completa de entrada/salida.

## Prompts

Además de las cuatro herramientas, el servidor registra cuatro **prompts** MCP que tu cliente puede ofrecer como acciones rápidas — cada uno convierte una petición habitual en un plan de llamadas a herramientas listo para ejecutar, sin descargar nada por sí mismo:

| Prompt                  | Argumentos                                                       | Qué hace                                                                                     |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `acquire_book`          | `title` (requerido), `author`, `format`, `language`              | Encuentra y confirma la edición de un libro que mejor coincide, y la descarga.               |
| `research_topic`        | `topic` (requerido), `kind` (`articles`/`books`/`both`), `limit` | Construye una lista de lectura de artículos y/o libros sobre un tema, los descarga y resume. |
| `get_paper`             | uno de `doi` o `citation`                                        | Obtiene un artículo concreto directamente por DOI, o lo busca por una cita en texto libre.   |
| `download_troubleshoot` | `md5`, `doi`, `error` (todos opcionales)                         | Obtiene un árbol de decisión para diagnosticar y recuperarse de una descarga fallida.        |

Consulta [Herramientas](/libgen-mcp/es/tools/#prompts) para ver la tabla completa de argumentos y el comportamiento de cada prompt.

## Preguntas frecuentes

### ¿Cómo instalo libgen-mcp?

Si tienes Node 18 o posterior, el camino más corto es npm: ejecuta `npx @jmrp.io/libgen-mcp`, o instálalo globalmente con `npm install -g @jmrp.io/libgen-mcp`. Si no, usa el binario precompilado: descarga el archivo para tu plataforma desde la página de [releases de GitHub](https://github.com/jmrplens/libgen-mcp/releases) (los archivos se llaman `libgen-mcp-<os>-<arch>`, cubriendo Linux, macOS y Windows en amd64 y arm64), hazlo ejecutable y colócalo en tu `PATH`. Es un único ejecutable totalmente estático sin nada más que instalar. Como alternativas puedes usar la imagen de Docker multi-arch `ghcr.io/jmrplens/libgen-mcp:latest` o, si ya tienes Go 1.27 o posterior, compilar desde el código fuente con `go install github.com/jmrplens/libgen-mcp/cmd/server@latest`.

### ¿Qué método de instalación debería usar?

Usa npm si ya hay Node en la máquina: `npx @jmrp.io/libgen-mcp` no necesita paso de instalación y mantiene el servidor al día por sí solo. Si no, usa el binario precompilado: es un único ejecutable estático que no necesita toolchain de Go, ni Docker, ni runtime. Elige Docker si prefieres contenedores o un comando sin instalación que tu cliente descarga en el primer arranque. Elige `go install` solo si ya tienes Go 1.27 o posterior y quieres compilar desde el código fuente. En Claude Desktop, la extensión `.mcpb` de un clic del último release es la opción más sencilla.

### ¿Cómo conecto libgen-mcp a Claude o VS Code?

Apunta tu cliente MCP al binario `libgen-mcp`; por stdio no hacen falta argumentos adicionales. En Claude Code, añade un servidor `libgen` con command `libgen-mcp` al `.mcp.json` de tu proyecto (o ejecuta `claude mcp add`). En Claude Desktop, abre la extensión `.mcpb` de un clic, o añade el mismo bloque `mcpServers` a `claude_desktop_config.json` usando una ruta absoluta en `command`. En VS Code, añade una entrada `libgen` a `mcp.json` con command `libgen-mcp` y type `stdio`.

### ¿libgen-mcp necesita un token o cuenta?

No. libgen-mcp no necesita ningún token, clave de API ni cuenta de Library Genesis para funcionar. Por stdio solo le das al cliente el comando que lanza el binario. Todas las opciones de configuración son variables de entorno opcionales con un valor por defecto seguro, así que el servidor funciona nada más instalarlo.
