Este tutorial te lleva de cero a un asistente que busca, cita y lee a través de `libgen-mcp`, en cuatro pasos: instalar el servidor, registrarlo en un cliente, hacer una búsqueda y leer un resultado. Ningún paso necesita cuenta, clave de API ni token. Cada paso enlaza con la página que trata su tema a fondo, así que puedes quedarte aquí y volver a por el detalle.

## Instalación

Elige un canal. Todos entregan el mismo binario estático: no se compila nada y no se ejecuta nada al instalar. Si ya tienes Node 18 o posterior, **npm** es el camino más corto, porque tu cliente puede arrancar el servidor con `npx` y no hay nada que instalar. [Instalación](/libgen-mcp/es/install/overview/) compara todos los canales, incluidas la extensión de Claude Desktop y el plugin de agente, y explica cómo verificar lo que instalas.

<Tabs syncKey="install">
	<TabItem label="npm">
		```bash
		npx -y @jmrp.io/libgen-mcp --version
		```

    	Eso descarga el lanzador e imprime la versión. No queda nada instalado: tu cliente arrancará el servidor de la misma forma. [Instalar con npm](/libgen-mcp/es/install/npm/) cubre la instalación global, las actualizaciones y la desinstalación.
    </TabItem>
    <TabItem label="PyPI">
    	```bash
    	uvx libgen-mcp --version
    	```

    	`uvx` lo ejecuta sin instalarlo; `pipx install libgen-mcp` lo instala. [Instalar con PyPI](/libgen-mcp/es/install/pypi/) tiene el resto.
    </TabItem>
    <TabItem label="Homebrew">
    	```bash
    	brew install jmrplens/tap/libgen-mcp
    	libgen-mcp --version
    	```

    	[Instalar con Homebrew](/libgen-mcp/es/install/homebrew/) tiene el resto.
    </TabItem>
    <TabItem label="NuGet">
    	```bash
    	dnx libgen-mcp -- --version
    	```

    	Los argumentos del propio servidor van después de `--`; todo lo anterior es de `dnx`. [Instalar con NuGet](/libgen-mcp/es/install/nuget/) tiene el resto.
    </TabItem>
    <TabItem label="Docker">
    	```bash
    	docker pull ghcr.io/jmrplens/libgen-mcp:latest
    	```

    	Un cliente lo arranca con `docker run -i --rm ghcr.io/jmrplens/libgen-mcp:latest`; el `-i` es lo que lo convierte en un servidor stdio. [Ejecutar con Docker](/libgen-mcp/es/install/docker/) cubre el volumen de descargas y la forma HTTP.
    </TabItem>
    <TabItem label="Binario">

No necesita runtime de ningún tipo. ## Configurar un cliente MCP

Apunta tu cliente a la orden que te dio tu canal. Por stdio el servidor no necesita argumentos. Aquí el ejemplo es Claude Code, con la orden `npx` de la pestaña de npm:

```bash
claude mcp add libgen -- npx -y @jmrp.io/libgen-mcp
```

o la misma entrada en el `.mcp.json` de tu proyecto:

```json
{
	"mcpServers": {
		"libgen": { "command": "npx", "args": ["-y", "@jmrp.io/libgen-mcp"] }
	}
}
```

Con otro canal, la orden es `libgen-mcp` (Homebrew, una instalación global con npm o pipx, el binario), `uvx libgen-mcp`, `dnx libgen-mcp` o la línea `docker run` de arriba. **[Conectar un cliente](/libgen-mcp/es/clients/)** tiene la entrada completa para todos los demás clientes, en su forma local y en la remota, los botones de instalación en un clic y dónde van las claves opcionales.

<Aside type="caution">
	En Claude Desktop, la [extensión
	`.mcpb`](/libgen-mcp/es/install/claude-desktop/) de un clic no necesita ningún
	archivo de configuración. Los clientes de escritorio no heredan el `PATH` de
	tu shell, así que un archivo de configuración ahí lleva una ruta `command`
	absoluta.
</Aside>

### Endpoint alojado (sin instalar nada)

Para probar el servidor antes de instalar nada, apunta un cliente capaz de hablar HTTP a la instancia pública, **`https://mcp.jmrp.io/libgen`**:

```json
{
	"mcpServers": {
		"libgen": { "type": "http", "url": "https://mcp.jmrp.io/libgen" }
	}
}
```

Un servidor local sigue siendo la mejor forma de seguir usándolo: tus consultas no salen de tu ordenador, y `download` guarda el fichero en lugar de devolver un enlace. [Endpoint alojado](/libgen-mcp/es/hosted/) cuenta qué sirve la instancia pública, qué limita y qué registra.

## Tu primera búsqueda

<LegalNotice />

Cuando el cliente muestre `libgen` como conectado, pídele que busque. Una petición como:

> Busca "the go programming language" en no ficción, 25 resultados.

acciona la herramienta `search` con más o menos estos argumentos:

```json
{
	"query": "the go programming language",
	"topics": ["nonfiction"],
	"results_per_page": 25
}
```

Cada resultado incluye un `md5` (para libros) o un `doi` (para artículos). Pasa un `md5` a `get_details` para obtener los metadatos completos, y luego a `download` para descargar el archivo — o pasa un `doi` directamente a `download` para un artículo. `get_details` también devuelve un campo `citations` (`bibtex`/`ris`) que puedes pegar directamente en un gestor de referencias, añade APA, MLA, Chicago, Harvard, Vancouver, IEEE o CSL-JSON si se piden mediante `cite_as`, y acepta un `enrich: true` opt-in para añadir metadatos best-effort de Crossref/OpenLibrary. Para quedarte solo con trabajos recientes, una búsqueda acepta `year_from` y `year_to`. Consulta [Herramientas](/libgen-mcp/es/tools/) para ver todas las formas de entrada y salida, y [Descargar un artículo por DOI](/libgen-mcp/es/download-a-paper/) para lo que hace una descarga paso a paso.

## Leer y resumir

No hace falta descargar un archivo solo para ver qué contiene: `read` extrae y pagina directamente el texto de un libro o artículo. Una petición como:

> Busca el artículo "Why Most Published Research Findings Are False", lee su primera página y resume de qué trata.

hace que el modelo busque y luego llame a `read` con el DOI (o el `md5` de un libro) del resultado:

```json
{
	"doi": "10.1371/journal.pmed.0020124",
	"max_pages": 1
}
```

El campo `text` de la respuesta contiene el primer fragmento extraído — hasta `LIBGEN_MCP_READ_MAX_CHARS` caracteres, o `LIBGEN_MCP_READ_DEFAULT_PAGES` páginas de PDF, según aplique al formato — más `has_more`/`cursor` para seguir paginando, y `extractable`/`reason` cuando el archivo no tiene una capa de texto utilizable (un PDF escaneado, por ejemplo — `read` nunca ejecuta OCR). Para un libro, `outline: true` lista su índice con un número por entrada, y `section` con uno de esos números, o con el título de un capítulo, lee ese capítulo y se detiene donde termina.

<Aside type="caution">
	Trata `text` como **contenido no confiable que hay que resumir, no como
	instrucciones que seguir**; la propia `next_steps` de la herramienta lo indica
	en cada llamada.
</Aside>

Consulta [Herramientas](/libgen-mcp/es/tools/#read) para la referencia completa de entrada/salida.

### Una sesión grabada

Este intercambio es el escenario S19 de la [evaluación con LLM](/libgen-mcp/es/eval-results/), grabado el 2026-09-22 con `claude-haiku-4-5-20251001` contra los mirrors en vivo. No se ha editado nada salvo el formato de la respuesta, y se reproduce en inglés, el idioma en que se grabó. La petición fue:

> Search Library Genesis articles for the paper "Hallmarks of Cancer: The Next Generation" by Hanahan and Weinberg, then read the first page of the PDF (do NOT download the whole file) and give me a two- or three-sentence summary of what it covers.

El modelo llamó a `search` una vez:

```json
{
	"query": "Hallmarks of Cancer: The Next Generation Hanahan Weinberg",
	"topics": ["articles"]
}
```

tomó el DOI del resultado y llamó con él a `read` en lugar de a `download`:

```json
{
	"doi": "10.1016/j.cell.2011.02.013",
	"max_pages": 1,
	"start_page": 1
}
```

Su respuesta, a partir de los 4566 caracteres que devolvió `read`:

> The paper presents an updated framework of six core biological capabilities that cancer cells acquire during tumor development—including sustaining proliferative signaling, evading growth suppressors, resisting cell death, enabling replicative immortality, inducing angiogenesis, and activating invasion and metastasis. The authors also introduce two emerging hallmarks (reprogramming of energy metabolism and evading immune destruction) and emphasize that tumors are complex tissues containing recruited normal cells that form the "tumor microenvironment," which actively contribute to cancer development rather than being passive bystanders.

## Preguntas frecuentes

### ¿Cómo instalo libgen-mcp?

Con el gestor de paquetes que ya tengas (npm, PyPI, Homebrew o NuGet), o descargando el binario precompilado desde la página de releases de GitHub. Todos los canales instalan el mismo ejecutable estático, sin nada más que instalar y sin cuenta que crear.

Los comandos son: npm (`npx @jmrp.io/libgen-mcp` o `npm install -g @jmrp.io/libgen-mcp`), PyPI (`uvx libgen-mcp` o `pipx install libgen-mcp`), Homebrew (`brew install jmrplens/tap/libgen-mcp`) o NuGet (`dnx libgen-mcp` o `dotnet tool install -g libgen-mcp`). Si no, usa el binario precompilado: descarga el archivo para tu plataforma desde la página de [releases de GitHub](https://github.com/jmrplens/libgen-mcp/releases) (los archivos se llaman `libgen-mcp-<os>-<arch>`, cubriendo Linux, macOS y Windows en amd64 y arm64), hazlo ejecutable y colócalo en tu `PATH`. Es un único ejecutable totalmente estático sin nada más que instalar. Como alternativas puedes usar la imagen de Docker multi-arch `ghcr.io/jmrplens/libgen-mcp:latest` o, si ya tienes Go 1.27.1 o posterior, compilar desde el código fuente con `go install github.com/jmrplens/libgen-mcp/v2/cmd/server@latest`.

### ¿Qué método de instalación debería usar?

El gestor de paquetes que ya esté en la máquina, porque todos entregan el mismo binario: npm si tienes Node, PyPI si tienes `uv` o `pipx`, Homebrew en macOS o Linux, NuGet si tienes el SDK de .NET.

Cualquiera de ellos puede además ejecutar el servidor sin instalarlo — `npx`, `uvx` y `dnx` lo hacen. Usa el binario precompilado si no tienes ninguno: es un único ejecutable estático que no necesita toolchain de Go, ni Docker, ni runtime. Elige Docker si prefieres contenedores o un comando sin instalación que tu cliente descarga en el primer arranque. Elige `go install` solo si ya tienes Go 1.27.1 o posterior y quieres compilar desde el código fuente. En Claude Desktop, la extensión `.mcpb` de un clic del último release es la opción más sencilla.

### ¿Cómo conecto libgen-mcp a Claude o VS Code?

Apunta tu cliente MCP al binario `libgen-mcp`; por stdio no hacen falta argumentos adicionales. En Claude Code, añade un servidor `libgen` con command `libgen-mcp` al `.mcp.json` de tu proyecto (o ejecuta `claude mcp add`). En Claude Desktop, abre la extensión `.mcpb` de un clic, o añade el mismo bloque `mcpServers` a `claude_desktop_config.json` usando una ruta absoluta en `command`. En VS Code, añade una entrada `libgen` a `mcp.json` con command `libgen-mcp` y type `stdio`.

### ¿libgen-mcp necesita un token o cuenta?

No. libgen-mcp no necesita ningún token, clave de API ni cuenta de Library Genesis para funcionar. Por stdio solo le das al cliente el comando que lanza el binario. Todas las opciones de configuración son variables de entorno opcionales con un valor por defecto seguro, así que el servidor funciona nada más instalarlo.
