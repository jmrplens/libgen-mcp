Everything else measured about this server is about its tool surface. None of it
tells you how much memory to give a container, how long a client waits before
its first call answers, or what a second caller adds to a deployment you are
already running. This page answers those, and every number on it comes from the
real binary rather than from an estimate.

The measurement runs **offline**: Library Genesis is stood in for by a server on
loopback serving a captured results page, so a second machine measures this
server rather than its own network.

<Aside type="note">
	These are one machine's numbers, and the machine is named below. They are
	useful as ratios — what a second caller adds, what a transport costs against
	the other — rather than as absolutes to plan capacity from on hardware that is
	not this.
</Aside>

## Reading these numbers

The resident set is read from the kernel rather than from inside the process. Go's
own heap figure is a different and smaller number, and only one of the two gets a
container OOM-killed.

Percentiles are nearest-rank, so every figure published is one the run actually
observed rather than a point interpolated between two calls nobody made. A
scenario whose calls failed does not finish at all: a search that cannot reach
its catalog answers in under a millisecond, and averaging that with a real one
would publish an error path as a cost.
