`libgen-mcp` has a formula in this project's own tap, [`jmrplens/homebrew-tap`](https://github.com/jmrplens/homebrew-tap). It installs the release binary for your machine, with its licence and third-party notices, and lets `brew upgrade` keep it current.

## What you get

The formula `libgen-mcp` downloads one release asset, the one for your system and architecture, and installs it as `bin/libgen-mcp`:

| System | Apple Silicon or arm64    | Intel or x86_64           |
| ------ | ------------------------- | ------------------------- |
| macOS  | `libgen-mcp-darwin-arm64` | `libgen-mcp-darwin-amd64` |
| Linux  | `libgen-mcp-linux-arm64`  | `libgen-mcp-linux-amd64`  |

Beside the binary it installs `LICENSE` and `THIRD_PARTY_NOTICES` in the keg, because the binary links modules whose licences ask for their texts to travel with it. Nothing is compiled: there is no build step, and no bottle is needed.

The formula is generated by the release workflow from the release's `checksums.txt` and pushed to the tap, so a new version is in the tap minutes after the release.

## Prerequisites

| Requirement | Detail                                         |
| ----------- | ---------------------------------------------- |
| Homebrew    | On macOS, or Homebrew on Linux                 |
| A platform  | macOS or Linux, on arm64 or x86_64. No Windows |

## Install

```bash
brew install jmrplens/tap/libgen-mcp
```

The fully qualified name taps `jmrplens/tap` on the way. The equivalent in two steps is `brew tap jmrplens/tap` followed by `brew install libgen-mcp`.

```bash
libgen-mcp --version
# libgen-mcp 2.1.0 (commit 5493887)
```

The install ends with a caveat naming the command to give your client, `$(brew --prefix)/bin/libgen-mcp`.

## Verify what you installed

**The formula pins each platform's asset by SHA256, and `brew` refuses a download that does not match.** The check is already done when the command returns. Those hashes are copied from the release's `checksums.txt`, the manifest the release signs, not computed from a fresh download, so the formula is as trustworthy as that signed manifest.

The installed binary is the release asset byte for byte, so its build provenance verifies it as well:

```bash
gh attestation verify "$(brew --prefix libgen-mcp)/bin/libgen-mcp" -R jmrplens/libgen-mcp \
  --signer-workflow jmrplens/libgen-mcp/.github/workflows/release.yml
```

What `--signer-workflow` adds is explained on the [installation overview](/libgen-mcp/install/overview/#verifying-what-you-install).

## Where it lands on disk

| Path                                                | What it is                       |
| --------------------------------------------------- | -------------------------------- |
| `$(brew --prefix)/bin/libgen-mcp`                   | The command, a link into the keg |
| `$(brew --prefix)/Cellar/libgen-mcp/<version>/bin/` | The binary                       |
| `$(brew --prefix)/Cellar/libgen-mcp/<version>/`     | `LICENSE`, `THIRD_PARTY_NOTICES` |

`brew --prefix` is `/opt/homebrew` on Apple Silicon, `/usr/local` on Intel macs and `/home/linuxbrew/.linuxbrew` on Linux. What the server writes once it runs is listed on the [installation overview](/libgen-mcp/install/overview/#what-every-channel-shares).

## Configure a client

```json
{
	"mcpServers": {
		"libgen": { "command": "/opt/homebrew/bin/libgen-mcp" }
	}
}
```

Use your own prefix. The full path matters here more than on other channels: a desktop client started from the Dock or a launcher does not read your shell profile, so it often does not have Homebrew's directory on its `PATH`. Where each client keeps this file is on [Connect a client](/libgen-mcp/clients/).

## Upgrade

```bash
brew update
brew upgrade libgen-mcp
```

`brew update` fetches the tap's new formula; `brew upgrade` on its own runs it first unless auto-update is turned off. A client that already has the server running keeps the old process until it restarts it; `libgen-mcp --shutdown` asks every running instance to exit.

## Pin a version

```bash
brew pin libgen-mcp     # brew upgrade leaves it where it is
brew unpin libgen-mcp   # follow releases again
```

The tap holds only the newest formula, so pinning keeps the version you have rather than installing an older one. To run a particular older release, use its [release binary](/libgen-mcp/install/binary/).

## Uninstall

```bash
brew uninstall libgen-mcp
brew untap jmrplens/tap   # if nothing else you use comes from it
```

Settings, caches and downloads are not touched; the overview lists [where they are](/libgen-mcp/install/overview/#what-every-channel-shares).

## Platform notes

- **No Gatekeeper prompt.** Homebrew does not set the quarantine attribute on what a formula installs, so macOS does not stop the first run of a binary that is not notarized.
- **Linux on arm64** is served by the formula's `on_arm` branch, like Apple Silicon.

## Common problems

**`Error: No available formula with the name "libgen-mcp"`.** Use the fully qualified name `jmrplens/tap/libgen-mcp`; the formula is not in homebrew-core.

**`brew upgrade` says it is already up to date right after a release.** The local tap is stale. `brew update` fetches it.

**The client cannot find `libgen-mcp`.** Give it the full path from `command -v libgen-mcp`, for the reason under [Configure a client](#configure-a-client).

Other channels are compared on the [installation overview](/libgen-mcp/install/overview/).
