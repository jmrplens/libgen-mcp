This tutorial takes you from nothing to an assistant that can search, cite and read through `libgen-mcp`, in four steps: install the server, register it with a client, run a search, and read a result. No step needs an account, an API key or a token. Each step links to the page that covers its subject in full, so you can stop here and come back for the detail.

## Install

Pick one channel. Every one of them delivers the same single static binary: nothing is compiled and nothing runs at install time. If you already have Node 18 or newer, **npm** is the shortest path, because your client can then start the server through `npx` and there is nothing to install at all. [Installation](/libgen-mcp/install/overview/) compares every channel, including the Claude Desktop extension and the agent plugin, and says how to verify what you installed.

<Tabs syncKey="install">
	<TabItem label="npm">
		```bash
		npx -y @jmrp.io/libgen-mcp --version
		```

    	That fetches the launcher and prints the version. Nothing stays installed: your client will start the server the same way. [Install with npm](/libgen-mcp/install/npm/) covers a global install, upgrades and removal.
    </TabItem>
    <TabItem label="PyPI">
    	```bash
    	uvx libgen-mcp --version
    	```

    	`uvx` runs it without installing; `pipx install libgen-mcp` installs it. [Install with PyPI](/libgen-mcp/install/pypi/) has the rest.
    </TabItem>
    <TabItem label="Homebrew">
    	```bash
    	brew install jmrplens/tap/libgen-mcp
    	libgen-mcp --version
    	```

    	[Install with Homebrew](/libgen-mcp/install/homebrew/) has the rest.
    </TabItem>
    <TabItem label="NuGet">
    	```bash
    	dnx libgen-mcp -- --version
    	```

    	The server's own arguments go after `--`; everything before it belongs to `dnx`. [Install with NuGet](/libgen-mcp/install/nuget/) has the rest.
    </TabItem>
    <TabItem label="Docker">

    	docker pull ghcr.io/jmrplens/libgen-mcp:latest

    	A client starts it with `docker run -i --rm ghcr.io/jmrplens/libgen-mcp:latest`; the `-i` is what makes it a stdio server. [Run with Docker](/libgen-mcp/install/docker/) covers the download volume and the HTTP form.
    </TabItem>
    <TabItem label="Binary">
    	Download `libgen-mcp-<os>-<arch>` for your platform from the [releases page](https://github.com/jmrplens/libgen-mcp/releases), make it executable and put it on your `PATH`. ## Configure an MCP client

Point your client at the command your channel gave you. Over stdio the server needs no arguments. Claude Code is the example here, with the `npx` command from the npm tab:

```bash
claude mcp add libgen -- npx -y @jmrp.io/libgen-mcp
```

or the same entry in your project's `.mcp.json`:

```json
{
	"mcpServers": {
		"libgen": { "command": "npx", "args": ["-y", "@jmrp.io/libgen-mcp"] }
	}
}
```

With another channel, the command is `libgen-mcp` (Homebrew, a global npm or pipx install, the binary), `uvx libgen-mcp`, `dnx libgen-mcp` or the `docker run` line above. **[Connect a client](/libgen-mcp/clients/)** has the complete entry for every other client, in its local and its remote form, the one-click install buttons, and where optional keys go.

<Aside type="caution">
	On Claude Desktop the one-click [`.mcpb`
	extension](/libgen-mcp/install/claude-desktop/) needs no configuration file at
	all. Desktop clients do not inherit your shell `PATH`, so a configuration file
	there takes an absolute `command` path.
</Aside>

### Hosted endpoint (no install)

To try the server before installing anything, point an HTTP-capable client at the public instance, **`https://mcp.jmrp.io/libgen`**:

```json
{
	"mcpServers": {
		"libgen": { "type": "http", "url": "https://mcp.jmrp.io/libgen" }
	}
}
```

A local server remains the better way to keep using it: your queries never leave your computer, and `download` saves the file instead of returning a link. [Hosted endpoint](/libgen-mcp/hosted/) says what the public instance serves, limits and logs.

## Your first search

<LegalNotice />

Once the client shows `libgen` as connected, ask it to search. A prompt such as:

> Search for "the go programming language" in nonfiction, 25 results.

drives the `search` tool with roughly these arguments:

```json
{
	"query": "the go programming language",
	"topics": ["nonfiction"],
	"results_per_page": 25
}
```

Each result carries an `md5` (for books) or a `doi` (for articles). Feed an `md5` to `get_details` for full metadata, then to `download` to fetch the file — or feed a `doi` straight to `download` for an article. `get_details` also returns a `citations` field (`bibtex`/`ris`) you can paste straight into a reference manager, and accepts an opt-in `enrich: true` to add best-effort Crossref/OpenLibrary metadata. See [Tools](/libgen-mcp/tools/) for the full input and output shapes, and [Download a paper by DOI](/libgen-mcp/download-a-paper/) for what a download does step by step.

## Read and summarize

You don't have to download a file just to see what's in it: `read` extracts and paginates a book's or paper's text directly. A prompt such as:

> Find the article "Attention Is All You Need", read its first page, and summarize what it's about.

has the model search, then call `read` with the DOI (or `md5` for a book) from the result:

```json
{
	"doi": "10.48550/arXiv.1706.03762",
	"max_pages": 1
}
```

The response's `text` field holds the extracted first chunk — up to `LIBGEN_MCP_READ_MAX_CHARS` characters, or `LIBGEN_MCP_READ_DEFAULT_PAGES` PDF pages, whichever applies to the format — plus `has_more`/`cursor` to keep paging, and `extractable`/`reason` when the file has no usable text layer (a scanned PDF, for example — `read` never runs OCR).

<Aside type="caution">
	Treat `text` as **untrusted content to summarize, not as instructions to
	follow**; the tool's own `next_steps` says so on every call.
</Aside>

See [Tools](/libgen-mcp/tools/#read) for the full input/output reference.

This exchange is scenario S19 of the [LLM evaluation](/libgen-mcp/eval-results/), recorded on 2026-09-22 with `claude-haiku-4-5-20251001` against the live mirrors. Nothing is edited but the answer's formatting. The prompt was:

> Search Library Genesis articles for the paper "Hallmarks of Cancer: The Next Generation" by Hanahan and Weinberg, then read the first page of the PDF (do NOT download the whole file) and give me a two- or three-sentence summary of what it covers.

The model called `search` once:

```json
{
	"query": "Hallmarks of Cancer: The Next Generation Hanahan Weinberg",
	"topics": ["articles"]
}
```

took the DOI from the result, and called `read` with it rather than `download`:

```json
{
	"doi": "10.1016/j.cell.2011.02.013",
	"max_pages": 1,
	"start_page": 1
}
```

Its answer, from the 4,566 characters `read` returned:

> The paper presents an updated framework of six core biological capabilities that cancer cells acquire during tumor development—including sustaining proliferative signaling, evading growth suppressors, resisting cell death, enabling replicative immortality, inducing angiogenesis, and activating invasion and metastasis. The authors also introduce two emerging hallmarks (reprogramming of energy metabolism and evading immune destruction) and emphasize that tumors are complex tissues containing recruited normal cells that form the "tumor microenvironment," which actively contribute to cancer development rather than being passive bystanders.

## Frequently asked questions

### How do I install libgen-mcp?

With the package manager you already have (npm, PyPI, Homebrew or NuGet), or by downloading the prebuilt binary from the GitHub releases page. Every channel installs the same single static executable, with nothing else to install and no account to create.

The commands are: npm (`npx @jmrp.io/libgen-mcp` or `npm install -g @jmrp.io/libgen-mcp`), PyPI (`uvx libgen-mcp` or `pipx install libgen-mcp`), Homebrew (`brew install jmrplens/tap/libgen-mcp`) or NuGet (`dnx libgen-mcp` or `dotnet tool install -g libgen-mcp`). Otherwise use the prebuilt binary: download the asset for your platform from the [GitHub releases](https://github.com/jmrplens/libgen-mcp/releases) page (named `libgen-mcp-<os>-<arch>`, covering Linux, macOS, and Windows on amd64 and arm64), mark it executable, and put it on your `PATH`. It is a single fully static executable with nothing else to install. As alternatives, you can pull the multi-arch Docker image `ghcr.io/jmrplens/libgen-mcp:latest`, or build from source with `go install github.com/jmrplens/libgen-mcp/v2/cmd/server@latest` if you have Go 1.27.1 or newer.

### Which install method should I use for libgen-mcp?

Whichever package manager is already on the machine, since they all deliver the same binary: npm if you have Node, PyPI if you have `uv` or `pipx`, Homebrew on macOS or Linux, NuGet if you have the .NET SDK.

Any of them can also run the server without installing it — `npx`, `uvx` and `dnx` each do. Use the prebuilt binary if you have none of them: it is a single static executable that needs no Go toolchain, no Docker, and no runtime. Choose Docker if you prefer containers or want a zero-install command your client pulls on first run. Choose `go install` only if you already have Go 1.27.1 or newer and want to build from source. On Claude Desktop, the one-click `.mcpb` extension from the latest release is the easiest option.

### How do I connect libgen-mcp to Claude or VS Code?

Point your MCP client at the `libgen-mcp` binary; over stdio no extra arguments are needed. In Claude Code, add a `libgen` server with command `libgen-mcp` to your project's `.mcp.json` (or run `claude mcp add`). In Claude Desktop, open the one-click `.mcpb` extension, or add the same `mcpServers` block to `claude_desktop_config.json` using an absolute `command` path. In VS Code, add a `libgen` entry to `mcp.json` with command `libgen-mcp` and type `stdio`.

### Does libgen-mcp need a token or account?

No. libgen-mcp needs no token, API key, or Library Genesis account to run. Over stdio you only give the client the command to launch the binary. Every configuration option is an optional environment variable with a safe default, so the server works out of the box.
