**LibGen MCP** is an [MCP](https://modelcontextprotocol.io) server, written in Go, for searching and downloading from **Library Genesis** (the `libgen.li` mirror family). It exposes four tools — `search`, `get_details`, `download`, and `read` — to any MCP-compatible client such as Claude Code, Claude Desktop, or your own agent.

Mirrors are discovered automatically and cached, with transparent failover, so the server keeps working as individual mirrors go up and down. Openly licensed books can be fetched by ISBN from OAPEN and the Internet Archive, and articles by DOI, through the open-access providers first (Unpaywall, Europe PMC, bioRxiv/medRxiv, Internet Archive Scholar, CORE, OAPEN) and then Sci-Hub and SciDB. `search` additionally consults keyless extra sources — Anna's Archive, arXiv, Crossref, OpenLibrary, Project Gutenberg, dblp, PubMed, and ERIC — merged, deduped, and labeled by origin alongside the usual Library Genesis results; the default `auto` reaches for them automatically whenever the catalog comes up empty.

## Install in one line

```sh
claude mcp add libgen -- docker run -i --rm ghcr.io/jmrplens/libgen-mcp:latest
```

Or point your client at a prebuilt binary — no account, API key or token at any
step. Full instructions, including the `mcpServers` JSON for Claude Desktop,
Cursor and VS Code, are in [Getting Started](/libgen-mcp/getting-started/).

## Which libgen-mcp is this?

Several unrelated projects share the name. This one is `jmrplens/libgen-mcp`,
registered as `io.github.jmrplens/libgen-mcp`:

|                  | This project                                                    |
| ---------------- | --------------------------------------------------------------- |
| Repository       | [`jmrplens/libgen-mcp`](https://github.com/jmrplens/libgen-mcp) |
| Language         | Go — a single static binary, no runtime to install              |
| Tools            | Four: `search`, `get_details`, `download`, `read`               |
| Download sources | Twelve, in a fixed chain, open access tried first               |
| Registry id      | `io.github.jmrplens/libgen-mcp`                                 |

What distinguishes it: the download chain is ordered so open-access providers
are exhausted before any shadow library is consulted, it refuses material it may
not redistribute, and its tool surface is checked against a live, graded
[LLM evaluation](/libgen-mcp/eval-results/) rather than asserted.

## Example prompts

You talk to your assistant, not to the tools — it picks the tool and the
arguments. Every prompt below is taken from the
[evaluation suite](/libgen-mcp/eval-results/), where a real model is graded on
handling it against the live site:

| Ask your assistant                             | What libgen-mcp does                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| "I want to read _Dune_ — can you find it?"     | Forms a catalog search unaided, with no collection or field hints                                      |
| "Download _Clean Code_ for me"                 | Searches, picks an md5 from the results, and chooses the download source itself                        |
| "Get me a PDF of _Hallmarks of Cancer_"        | Works out that articles are keyed by DOI, not md5, and resolves it through the open-access chain       |
| "Find this paper and summarize the first page" | Calls `read` instead of `download`, and summarizes the extracted text rather than dumping it           |
| "What does this book say about pointers?"      | Calls `read` with `find`, searching inside the document without fetching the whole file                |
| "Give me its table of contents"                | Calls `read` with `outline=true`, and compiles one from the text when the file embeds none             |
| "Get me this book by its ISBN"                 | Routes to OAPEN and public-domain Internet Archive scans — never a shadow-library fallback             |
| "Give me the direct link, don't download it"   | Sets `resolve_only` and returns a URL instead of writing a file                                        |
| "Also check the open-access literature"        | Sets `extra_sources` to `always` and merges arXiv, Crossref, PubMed and the rest alongside the catalog |

## Responsible use

<Aside type="caution">
	This tool accesses third-party mirrors of Library Genesis. You are responsible
	for respecting the copyright and intellectual-property laws that apply where
	you live. Use it only for content you are legally entitled to access.
</Aside>

libgen-mcp tries the legal open-access providers before any shadow-library
fallback, and refuses material it may not redistribute. [Responsible
use](/libgen-mcp/responsible-use/) sets out what that means in practice, what the
server declines to do, and how to raise a concern.

## Frequently asked questions

### What is libgen-mcp?

libgen-mcp is an open source Model Context Protocol (MCP) server, written in Go, for searching and downloading from Library Genesis (the `libgen.li` mirror family). It exposes four tools — `search`, `get_details`, `download`, and `read` — to any MCP-compatible client such as Claude Code, Claude Desktop, or your own agent, so you can search books, resolve download links, and read/summarize text in plain language.

### What can libgen-mcp do?

It searches the Library Genesis catalog, returns per-result metadata and MD5 hashes, fetches full details for a record, and downloads files to a local directory. Books are downloaded by MD5 from LibGen, and by ISBN from the openly licensed book sources OAPEN and the Internet Archive; articles are fetched by DOI through the open-access providers first — Unpaywall, Europe PMC, bioRxiv/medRxiv, Internet Archive Scholar, CORE, and OAPEN — then Sci-Hub and SciDB. The `search` tool also consults keyless extra sources — Anna's Archive, arXiv, Crossref, OpenLibrary, Project Gutenberg, dblp, PubMed, and ERIC — merged and deduped alongside the Library Genesis results; by default (`auto`) it does so automatically whenever the catalog comes up empty. Mirrors are discovered automatically and cached, with transparent failover, retry with cooldown, and a shared rate limiter, so the server keeps working as individual mirrors go up and down.

### Do I need an account, API key, or token to use libgen-mcp?

No. libgen-mcp requires no Library Genesis account, no API key, and no token. Every option is an environment variable with a documented default, so the server runs with zero configuration. The only email-shaped setting is the optional `LIBGEN_MCP_UNPAYWALL_EMAIL` contact address sent to the Unpaywall API for DOI lookups. It is unset by default, which disables the Unpaywall source — the keyless open-access sources (Europe PMC, bioRxiv/medRxiv, Internet Archive Scholar) and the Sci-Hub/SciDB fallbacks still serve DOIs without it. Set your own address to enable Unpaywall. The one other optional credential is `LIBGEN_MCP_CORE_KEY`, a free CORE API key that enables the `core` open-access source.

### Is libgen-mcp free and open source?

Yes. libgen-mcp is free and open source under the MIT license. The full source code is on GitHub at [github.com/jmrplens/libgen-mcp](https://github.com/jmrplens/libgen-mcp), and prebuilt binaries, a Docker image, and a Claude Desktop extension are published with each release.

### Does libgen-mcp prefer legal sources?

Yes, by design. The download chain is ordered so the open-access providers are tried first: an article requested by DOI goes to Unpaywall, Europe PMC, bioRxiv/medRxiv, Internet Archive Scholar, CORE and OAPEN before Sci-Hub or SciDB are considered at all, and a book requested by ISBN comes only from OAPEN and public-domain Internet Archive scans. The server also refuses material it may not redistribute: it confirms an OAPEN identifier instead of accepting a free-text match, skips lending-restricted Internet Archive scans, and drops Project Gutenberg records hosted by permission rather than in the public domain. A refusal is reported as a miss, never dressed up as a file.
